# 경매 프로그램 검증 문서

> 분류: **2026-09-17 실측·증거 기록**. 컨트롤러·MAUI 관찰 결과이며 현재 WPF의 검증 결과와 구분한다. 문서의 “최신”은 해당 관찰 시점 내 비교다.
> [현재 WPF 수신 기능](../기능/경매수신_데이터갱신.md) · [전체 문서 목차](../README.md)

단일경매와 일괄경매에서 실제 버튼을 조작해 관찰한 결과와 MAUI 수신 코드를 구분한다.

- [단일경매 버튼별 MAUI 실제 수신](단일경매_버튼별_MAUI실수신.md): **최신 단일 검증**. 시작·정지·취소·낙찰/유찰·보조 버튼·일괄 모드 복원과 야간 자동 종료 기록.
- [단일 MAUI 실수신 증거표](단일경매_MAUI실수신_증거표.md): 재시작별 수신 순서와 실패 시도 구분.

- [일괄경매 버튼별 MAUI 실제 수신](일괄경매_버튼별_MAUI실수신.md): **최신 확인**. 기존 앱의 디코더를 직접 관찰한 버튼 → 컨트롤러 송신 → MAUI 수신 → 코드 처리 대응표.
- [MAUI 실수신 시각·순서 증거표](일괄경매_MAUI실수신_증거표.md): 추적 구간별 신호 순서와 SS 건수.
- [일괄경매 실측·사용법](일괄경매_실측_2026-09-17.md): 시작·응찰·정지·재개·종료·단축키 차이와 보완 검증.
- [일괄경매 관찰 증거표](일괄경매_실측_증거표.md): 버튼별 시각·코드 건수.
- [단일경매 버튼별 실측](단일경매_버튼별_실측.md): 버튼·활성 조건·실제 로그·화면·검증 한계.
- [단일경매 수신 처리 코드 대조](단일경매_수신처리_코드대조.md): 프로토콜 필드, 상태 처리, 무시 신호, HTTP 조회 경로.
- [실측 시각과 코드 건수](단일경매_실측_증거표.md): 원문·식별값 없는 관찰 구간별 근거.

- [실수신 진단 검증 계획과 후속 결과](실수신_진단검증_계획.md): 재시작안은 미실행. 대신 기존 프로세스에 디버거 추적점을 연결해 일괄 실수신을 확인하고 해제함.

핵심: F5는 새로고침, F6는 강제낙찰/유찰이다. 화면의 `구분: 일괄`과 실제 단일경매 방식은 구분해야 한다. 컨트롤러 송신 로그를 MAUI 수신 원문으로 취급하지 않는다. 직접 수신 진단이 없는 항목은 미확인 상태를 유지한다.

위 F6 설명은 단일모드 UI 기준이다. 일괄모드에서는 경매시작·경매정지·경매종료 버튼을 사용한다. 일괄 F9–F12의 CZ가 MAUI에 SZ로 도착하는 것, 새로고침 때 AS8001이 추가로 도착하는 것, 재진입 시 AT10은 일괄 실수신 문서에서 확인했다. 단일 후속 검사에서는 취소 SD(F)→AF24→AS8002, 강제 결과 AS8006→AF22/23을 확인했다. 모든 버튼·조건을 전수 검증했다는 뜻은 아니며 직접 수신 미확정 항목은 각 문서의 한계 표를 참조한다.

23시 이후 MAUI는 기존 NightSchedule 정책으로 자동 종료됐다. 같은 실행 파일로 재시작해 검사를 이어갔고, 원래 일괄 모드와 구간을 복원했다. Chrome·컨트롤러를 종료하지 않았으며 users.XML 두 파일의 해시가 시작 전과 같은 것을 확인했다.
