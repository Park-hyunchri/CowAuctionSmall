# 일괄경매 실측·사용법

**후속 갱신:** 아래는 22:02–22:08의 화면·컨트롤러 로그 검증이다. 이후 22:31–22:41에 [MAUI 디코더 실제 수신](일괄경매_버튼별_MAUI실수신.md)을 확인했다. 아래 CZ 중계 미확인 항목은 후속 검증에서 `CZ → SZ`로 확인됐고, 재진입의 AT10도 확인됐다. 전용 표시 구현의 제한은 그대로 구분한다.

2026-09-17 22:02–22:08 KST, 가짜 데이터 환경에서 실제 마우스와 키보드로 검증했다. 컨트롤러·Chrome·MAUI는 기존 프로세스를 유지했다. 소스와 실행 폴더의 `users.XML` 내용·파일명, 개체 이름은 변경하지 않았다. 기존 WPF는 읽기 전용으로 비교했다.

## 실제 조작 순서

1. 컨트롤러 하단 **경매시작**을 클릭하고 확인창에서 확인한다. 이번에는 대기·보류 개체 197두가 진행 대상으로 선택됐다.
2. 브라우저 숫자패드로 **경매번호 → 확인 → 금액 → 응찰**을 누른다. 이번에는 5번에 500을 입력했고 `응찰되었습니다` 안내를 확인했다. 단일경매와 달리 번호 입력 단계가 있다.
3. 컨트롤러 **경매정지**로 멈춘다. **경매시작 → 확인**으로 재개한다. 기존 500 응찰은 유지됐다.
4. **경매종료 → 확인**으로 결과를 확정한다. 이는 프로그램 창 종료와 다르다. 5번은 500 낙찰, 무응찰 표본은 컨트롤러에서 보류로 표시됐다.
5. 브라우저 목록이 이전 값이면 F5로 새로고침한다. 이번에는 새로고침 전 5번이 0/대기, 이후 500/낙찰로 바뀌었다. 컨트롤러의 F5는 목록 재전송과 대기 상태 전환을 동반하므로 브라우저 F5와 구분한다.

**일괄경매 단축키는 단일경매와 달랐다.** 진행 중 Space를 눌러도 정지하지 않았다. Esc는 `종료하시겠습니까?` 확인창을 열었으며, 창 유지 조건에 따라 **취소**했다. 일괄경매에서 Esc를 경매 취소로 안내하면 안 된다. 시작·정지·종료는 화면의 해당 버튼으로 조작한다.

## 판정과 제한

- 일괄 시작 → 번호 지정 응찰 → 정지 → 재개 → 낙찰 결과의 핵심 흐름은 실제 세 프로그램에서 확인했다. 보류/유찰 명칭은 컨트롤러와 전광판에서 달랐으므로 같은 문구라고 기록하지 않는다.
- MAUI는 일괄 진행 시 전체 칸을 단일경매 진행 화면으로 바꾸지 않는다. WPF에도 같은 로직이 있다. 요구가 확정되지 않은 화면 의미는 임의로 변경하지 않았다.
- 브라우저 목록의 종료 직후 갱신 지연은 외부 사이트 영역이다. 새로고침으로 결과를 확인했으며 MAUI 수정으로 해결했다고 기록하지 않는다.
- F9–F12는 컨트롤러에서 CZ를 보낸다. MAUI 업무 처리에는 SZ 분기가 있지만 CZ 분기는 없다. 중계 서버가 무엇을 MAUI에 전달했는지는 현재 실행본의 로그만으로 확정할 수 없다. 이를 임의로 같은 프로토콜로 취급하지 않았다.
- 기존 앱을 종료하지 않았으므로 이후 소스 보완은 현재 실행 중인 MAUI에 적용되지 않는다. 현재 창의 실제 검증과 수정본 자동 검증을 구분한다.
- 설정 저장, 프로그램 종료, 실제 금전 거래, 장시간 운전·여러 참가자의 경쟁 응찰은 수행하지 않았다.

## 보완 범위

코드 감사에서 일괄 진행 플래그의 수명 문제가 발견됐다. 초기 목록 전에 시작 신호가 오면 플래그가 설정되지 않고, 회차 종료나 단일 방식 전환 뒤에도 플래그가 남을 수 있다. 이 플래그는 조회 주기에 영향을 준다. 화면 전체를 진행 상태로 강제 변경하지 않고 상태 시작·해제와 테스트를 보완했다. 수정 전 신규 검사 5개 중 4개 실패, 수정 후 관련 20개 통과 및 별도 Debug 빌드 성공(기존 경고19·오류0). 실제 변경 파일·명령·검증 한계는 [WORKLOG](../../WORKLOG.md)의 이번 일괄경매 항목을 참조한다.

## 근거 보존

화면 캡처·조작 구간별 비식별 JSON은 Git에서 제외되는 `artifacts/batch-mode`에 보관했다. 문서에는 원문 응답, 인증값, 이름, 개체 식별번호를 옮기지 않았다. 번호 5와 입력 500은 테스트 조작 설명이다. `Tools/Inspect-DesktopWindow.ps1`은 창 소유 PID·전경·가림을 검사한 뒤 입력한다. 재실행 시 창 핸들과 좌표를 새로 확인해야 한다.
