# 단일경매 수신 처리 코드 대조

확인일: 2026-09-17. 현재 MAUI 작업 트리의 코드와 별도로 전달받은 컨트롤러 관찰 결과를 구분해 기록한다. 이 문서 작성 과정에서는 소스·설정을 변경하거나 프로그램을 재시작하지 않았고, 빌드·테스트도 실행하지 않았다.

## 증거의 범위

- **코드 확인**: 특정 신호가 MAUI에 도착했을 때 수행하는 처리이다. 실제 해당 신호가 도착했다는 증거는 아니다.
- **컨트롤러 관찰**: 컨트롤러 로그에 기록된 송수신이다. 수신자에 따라 다른 신호가 전달될 수 있어 MAUI 수신과 동일하게 취급하지 않는다.
- **MAUI 결과 확인**: 화면 변화와 `single-auction-complete` 등의 진단이다. 개별 수신 패킷의 원문·순서를 증명하지 않는다.

현재 실행 중인 MAUI에는 패킷 코드별 수신을 파일에 기록하는 진단 경로가 없다. 앱 유지·추가 인증 연결 없음 조건으로 수신 원문을 읽을 수 있는 기존 경로도 확인되지 않았다. 컨트롤러의 `CF`가 서버에서 MAUI용 `AF`로 변환되는지 같은 중계 동작은 **미확인**이다. 원본 패킷, 인증값, 사업장·참가자·개체 식별값은 문서에 기록하지 않는다.

F5 새로고침 실측에서 컨트롤러 로그에 `CD` 1건, `CI` 501건, `AS 8002` 1건이 관찰되었다. **AS8001 송신은 관찰되지 않았다.** 따라서 아래 AS8001→SV 경로는 코드에 존재하는 조건부 경로이며, 이번 F5에서 실행됐다는 뜻이 아니다.

## 경매 방식과 화면 구분

| 구분 | 의미와 현재 코드 |
|---|---|
| `AT[2]=20` | MAUI 수신 처리기의 단일경매 방식. `NettyAsyncMsgProcess._auctionmethod`에 저장한다. |
| `AT[2]=10` | MAUI 수신 처리기의 일괄경매 방식. `20` 이외 값을 모두 일괄로 승인하는 것은 아니며, AT 파서는 `10/20`만 받아들인다. |
| `AS[13]` | 소스 주석의 경매유형 구분: `0` 일괄, `1` 송아지, `2` 비육우, `3` 번식우. 현재 AS 처리기는 이 필드로 `_auctionmethod`를 정하지 않는다. |
| 컨트롤러의 화면상 구분·표시 문구 | 경매 방식과 별도의 표시일 수 있다. 화면에 “일괄”이 보인다는 이유만으로 AT10 수신 또는 단일 처리 해제를 단정하지 않는다. |
| 여러 전광판 칸·페이지를 동시에 표시 | Board.XML의 보드 배치 및 페이지 설정이다. 다수 개체를 함께 표시한다고 AT10 경매라는 뜻은 아니다. |

근거: [AT 처리, 220행](../../CowAuctionMaUI.Application/Auction/NettyAsyncMsgProcess.cs#L220), [AS 필드 주석과 처리, 160행](../../CowAuctionMaUI.Application/Auction/NettyAsyncMsgProcess.cs#L160), [보드 배치 구성, 158행](../../CowAuctionMaUI/Runtime/AuctionDisplaySession.cs#L158).

`_auctionmethod`의 초기값은 `0`이다. AS 처리기의 `else`가 곧 “AT20 확인 완료”를 뜻하지 않으며, 이후 `ServerGetData`는 전달 배열의 방식이 `20`인지 다시 검사한다. 방식 미확정 상태의 동작을 정상 단일 처리로 확대 해석하지 않는다.

1. [AuctionShareNettyClient, 217행](../../CowAuctionMaUI.Infrastructure/Netty/netty/AuctionShareNettyClient.cs#L217): 줄바꿈 기준 프레임과 UTF-8 문자열을 처리한다.

3. [문자열 핸들러, 25행](../../CowAuctionMaUI.Infrastructure/Netty/netty/handlers/AuctionClientDecodedCurrentEntityInfoHandler.cs#L25) → [NettyControllable, 87행](../../CowAuctionMaUI.Infrastructure/Netty/netty/NettyControllable.cs#L87): `|`로 분리하여 `DataStringArrMessage`를 발행한다.
4. [NettyAsyncMsgProcess, 65행](../../CowAuctionMaUI.Application/Auction/NettyAsyncMsgProcess.cs#L65): 배열을 복사하고 [AuctionInput](../../CowAuctionMaUI.Application/Auction/AuctionInput.cs#L19)으로 의미를 분류한 뒤 `AuctionIngress`에 전달한다.
5. [ServerGetData](../../CowAuctionMaUI.Application/Auction/ServerGetData.cs#L921): 경매 상태·HTTP 결과를 반영하고 `DataChangedMessage`를 발행한다.
6. [AuctionDisplaySession.Receive, 201행](../../CowAuctionMaUI/Runtime/AuctionDisplaySession.cs#L201): 표시 대상을 갱신하고 불변 화면 스냅샷을 구성한다.

`AuctionInput`은 AT·AF·SZ 및 AS8001/8004/8006/8007을 기존 비동기 요청 세대를 바꾸는 입력으로 분류한다. 이전 세대 HTTP 응답이 최신 상태를 덮지 않게 하는 경계이며, 모든 문자열이 화면 변경을 일으키는 것은 아니다.

## 직접 처리하지 않는 신호

`AD`, `SC`, `AV`, `AY`, `CF`, `CU`, `CS`, `AB`, `CA`, `AI`, `SI`, `CD`, `CI`는 현재 업무 switch에 별도 case가 없다. 이 문자열이 MAUI까지 들어온다면 디코더 기본 분기를 거쳐 전달된 뒤 업무 처리 기본 분기에서 종료된다.

근거: [디코더 default, 128행](../../CowAuctionMaUI.Infrastructure/Netty/netty/handlers/AuctionClientInboundDecoder.cs#L128), [업무 switch, 113행](../../CowAuctionMaUI.Application/Auction/NettyAsyncMsgProcess.cs#L113).

- CU 관찰을 MAUI의 직접 일시 정지 처리로 표현하지 않는다.
- CF 관찰을 MAUI의 직접 취소/낙유찰 처리로 표현하지 않는다.
- CS·SD 카운트다운을 MAUI 화면의 초 단위 카운트 표시 구현으로 표현하지 않는다.
- AB 응찰 관찰을 MAUI의 직접 응찰가 처리로 표현하지 않는다.
- 컨트롤러의 CI/CD 다량 전송은 다른 수신자용일 수 있다. 이번 F5 관찰 건수를 MAUI 수신·처리 건수로 옮기지 않는다.
- `AnimalParseData`의 API 행 파싱과 Netty의 SC 직접 처리는 다른 경로다. API 데이터에 SC 형태가 있어도 Netty SC 처리기가 있다는 뜻은 아니다.

## 현재 확인 한계

- 이 문서는 코드 대조이며 모든 버튼의 실제 수신·상태 전이를 검증한 결과표가 아니다.
- 컨트롤러/서버/브라우저 구현 소스는 조사하지 않았다. 다른 기기용 코드의 정확한 의미나 서버 변환 규칙은 단정하지 않는다.
- 실행 중 MAUI의 패킷 원문과 순서가 없어 송신 버튼→서버 중계→MAUI 수신을 전 구간 직접 연결한 증거는 없다.
- 버튼 실측 문서에는 컨트롤러 로그, MAUI 화면, MAUI 진단을 별도 열로 기록하고, 미관찰 신호를 코드상 가능성만으로 실제 발생한 것처럼 채우지 않는다.
