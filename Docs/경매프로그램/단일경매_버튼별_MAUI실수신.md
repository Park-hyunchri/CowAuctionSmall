# 단일경매 버튼별 MAUI 실제 수신

2026-09-17 22:48~23:10 KST의 확인된 구간을 기록한다. 컨트롤러 버튼 조작, MAUI 업무 처리 진입 추적, 앱 로그를 구분한다. 이 문서만으로 모든 버튼·모든 경매 상태가 정상이라고 판정하지 않는다. 표식별 순서는 [실수신 증거표](단일경매_MAUI실수신_증거표.md)를 참조한다.

이전 [단일경매 버튼별 실측](단일경매_버튼별_실측.md)은 21시대 컨트롤러 중심 기록이다. 그때의 AT20·AS8001 미관찰을 지우거나 이번 관찰 시각으로 바꾸지 않는다. 이번 후속 검사에서는 MAUI의 AT20 및 AS8001을 실제로 관찰했다. [일괄경매 실제 수신](일괄경매_버튼별_MAUI실수신.md)은 별도 모드·별도 관찰이며 단일경매 증거를 대신하지 않는다.

## 관찰 경계와 자료의 한계

1. 초기에는 Visual Studio 함수 추적점으로 `AuctionClientInboundDecoder.Decode` 진입을 관찰했다. 대량 SV를 한 건씩 평가하는 과정에서 지연·연결 끊김·재연결이 발생했다. 측정이 실행에 영향을 준 구간이므로 정상 성능이나 버튼별 즉시 도착 순서를 판단하는 자료로 사용하지 않는다.
2. `single-business-boundary` 표식인 **22:56:35.1669868**부터 `NettyAsyncMsgProcess.NettyCodeProcess` 진입으로 경계를 옮겼다. 이 지점은 디코더 다음의 직렬 업무 처리 경계다. 해당 지점에 도착한 코드 순서는 확인할 수 있지만 TLS 수신 시각이나 전체 원본 패킷 수신 순서와 같다고 단정하지 않는다.
3. **SV와 SS는 업무 경계 추적 대상이 아니다.** 이후 표에서 SV·SS가 없다고 해서 네트워크로 오지 않았다는 뜻은 아니다. AS·AF·SD 등도 분기 진입을 확인한 것이며, HTTP 보정 성공·최종 화면·저장 성공까지 자동으로 증명하지 않는다.
4. 기록에는 코드, AS 상태, AT 방식, SZ 표시 종류, AF 결과, SD C/F만 남긴다. 원본 패킷·인증값·사업장·참가자·개체 식별값은 이 문서에 옮기지 않는다. SD의 초 숫자는 수집하지 않았다.
5. 재시작 후 Visual Studio 출력이 초기화되면서 최초 추적 파일이 덮어써졌다. `pre-restart-reviewed.txt`는 그 전에 도구로 읽은 안전한 행을 복사한 **검토 발췌 재구성본**이다. 원본 파일 복구본이나 전체 원본 추적이라고 표현하지 않는다. `first-restart-received.txt`는 첫 재시작 구간의 별도 보관본이다.

초기 디코더 검토에서 AT 방식은 `10 → 20 → 20`으로 관찰됐다. AT10 상태에서 단일 전환·재접속을 거쳤다는 범위를 구분하며, 초기 전체 기간을 모두 단일경매라고 취급하지 않는다. 업무 경계 이후 표는 단일 전환 후의 조작이다. UI의 `구분: 일괄`이나 날짜 선택의 축종 분류와 `AT[2]=20` 단일 경매 방식은 별개다.

## 유효 응찰 후 강제 낙찰

최종 재시도에서는 컨트롤러 화면 `28-bid-before-force.png`의 응찰금액 영역에 **400**이 반영된 것을 확인했다. 해당 이미지는 Git 제외 로컬 증거이며 식별 정보가 있어 본문에 삽입하지 않는다. 이 값은 테스트 입력 확인용이며 원본 패킷 가격을 추적 로그에 저장한 것이 아니다.

## 코드 해석과 남은 범위

- AS8004는 단일 진행 표시 경로, AS8006은 진행 해제 경로다. AF22/23은 결과코드 적용과 HTTP 보정 요청, AF24는 취소 종료 경로다. **이번 강제 결과의 관찰 순서는 AS8006 다음 AF였다.** 코드가 AF를 우선 종료 신호로 취급한다는 설명을 실제 수신 순서와 혼동하지 않는다.
- SD(F)는 업무 경계에 진입하지만 최종 SD 상태 처리 분기는 비어 있다. 수신 확인이 독립 정지 화면 구현 완료를 뜻하지 않는다.
- AS8001 다음 SV의 차수 지정 Refresh는 조건부 코드 경로다. 업무 추적 구간에는 SV를 볼 수 없으므로 해당 경로의 실행 여부를 추적 부재만으로 판단하지 않는다.
- 추적점 실행 지연, 자동 야간 종료, 재시작으로 나뉜 세션을 구분했다. 이 기록은 성능 측정이나 장시간 안정성 검증 결과가 아니다.
- 위 표의 직접 수신 미확정 버튼, 최종 화면 픽셀·이력 비고, 실제 음성 출력, 서버 저장·브라우저 복원은 후속 증거가 필요하다. 검사하지 않은 항목을 전체 정상으로 표시하지 않는다.

처리 코드는 [프로토콜 분기](../../CowAuctionMaUI.Application/Auction/NettyAsyncMsgProcess.cs), [조회·종료 처리](../../CowAuctionMaUI.Application/Auction/ServerGetData.cs), [Windows 수명](../../CowAuctionMaUI/Platforms/Windows/WindowLifecycle.cs), [야간 종료 정책](../../CowAuctionMaUI/Runtime/ApplicationLifetime.cs)을 참조한다. 상세 코드 대조는 [기존 코드 문서](단일경매_수신처리_코드대조.md)에 있다. 코드의 존재와 각 실행본에 실제 적용된 변경 범위는 별도로 확인해야 한다.

이번 목표에서는 제품 소스·빌드·테스트를 추가 변경/실행하지 않고 조작·로그 관찰·문서 정리를 수행했다. 기존 수정 사항은 별도로 남아 있으며 실행 중인 기존 Debug 바이너리에 최신 소스 변경이 모두 적용됐다고 가정하지 않는다. 원래 Chrome·컨트롤러 PID와 시작 시각을 유지했고, MAUI는 야간 정상 종료 후 같은 실행 파일로 재실행했다. 기존 MAUI가 계속 살아 있었다고 보고하지 않는다.

원래 일괄 모드·1~250 구간을 복원하고 임시 추적점 삭제 및 Detach를 완료했다(디버거 Mode1, 연결0, 추적점0). source/Debug `users.XML` 두 파일의 최종 SHA-256은 시작 전과 일치한다. 가짜 응찰·유찰·낙찰 결과는 테스트 데이터에 남아 있다. 가격 복원과 업무 결과 전체 복원은 다르다. 커밋·푸시는 수행하지 않았다.

문서 마무리 시 기존 실행 파일을 디버거 없이 다시 열었다. 야간 종료 정책은 그대로이므로 23시~1시에는 약200초 주기 검사에서 다시 종료될 수 있다. 재실행 사실을 야간 장시간 실행 성공으로 해석하지 않는다. 증거표58행의 시각·순서를 별도 검토자가 대조해 불일치0을 확인했고, 경매프로그램 문서의 로컬 링크92개와 diff 검사를 통과했다. 이 단계는 문서·실측 검증이며 새 제품 빌드/테스트 결과가 아니다.
