# 중복접속(2002) 재접속 정책 적용 절차

## 1. 문서 목적
- 중복접속(`AR ... 2002`) 상황에서 불필요한 재접속 루프를 제거한다.
- 네트워크 장애 복구 성능은 유지하고, 로그 스팸을 줄인다.
- 단계별 게이트를 둬서 순차적, 절차적, 유지보수 가능한 방식으로 적용한다.

## 2. 적용 원칙
1. `2002`는 네트워크 장애가 아니라 세션 상태 문제로 분리 처리한다.
2. 재접속 루프는 `disconnect/timeout`에만 적용한다.
3. 한 단계 완료 기준을 통과해야 다음 단계로 진행한다.
4. 각 단계는 작은 변경 단위로 나누고, 빌드/로그/동작 확인을 남긴다.
5. 롤백이 쉬운 구조(상태 분기, 단일 책임 메서드)로 구현한다.

## 4. 단계별 적용 계획
## Step 1. 연결 결과 모델 정리
- 목표: `bool` 성공/실패를 상태형으로 바꿔 정책 분기 기반 마련.
- 변경:
  - `ServerConn.NettyComm` 반환형을 `enum`으로 변경.
  - 예: `Connected`, `Duplicate`, `Timeout`, `Failed`.
- 완료 기준:
  - 컴파일 성공.
  - 기존 `2000` 성공 흐름 유지.

## Step 2. `2002` 전용 쿨다운 도입
- 목표: 중복접속에서 즉시 재시도를 막아 루프 차단.
- 변경:
  - `ServerGetData.EnsureNettyConnectionAsync`에 `DuplicateCooldownUntil` 도입.
  - `Duplicate` 수신 시 즉시 재연결 중단, 지정 시간(예: 30~60초) 이후만 재시도.
- 완료 기준:
  - `AR 2002` 연속 수신 시 초당 재연결 시도가 멈춤.
  - 쿨다운 만료 후 재시도 1회만 수행.

## Step 3. 장애 전용 백오프 재시도
- 목표: 실제 장애에서만 점진 재시도.
- 변경:
  - `Timeout/Failed/Disconnect`에만 백오프(1,2,4,8...최대 60초) 적용.
  - `Duplicate`에는 백오프 미적용.
- 완료 기준:
  - 장애 시 재시도 간격이 증가.
  - 중복접속 시 백오프 루프 미진입.

## Step 4. 로그 스로틀링 및 상태 전이 로그
- 목표: 로그 중복을 줄이고 필요한 신호만 남김.
- 변경:
  - `중복 접속`, `DISCONNECT` 로그를 상태 전이 시점 위주로 기록.
  - 동일 메시지 반복은 일정 주기 요약 로그로 대체.
- 완료 기준:
  - 동일 원인 반복 로그가 현저히 감소.
  - 최초 발생/복구/재시도 시작 로그는 유지.

## Step 5. 종료 시 세션 정리 보장
- 목표: 앱 종료 후 유령 세션 최소화.
- 변경:
  - `OnExit` 경로에서 Netty dispose 호출 보장.
  - 종료 중복 호출에도 안전한 idempotent 종료 처리.
- 완료 기준:
  - 종료 후 즉시 재실행 시 `2002` 발생 빈도 감소.

## Step 6. 통합 검증 및 운영 체크
- 목표: 현장 시나리오 기준 최종 확인.
- 검증 시나리오:
  1. 정상 연결(`2000`) 5회 반복.
  2. 중복접속(`2002`) 상태 1분 유지.
  3. 네트워크 단절 후 복구.
  4. 앱 종료 후 즉시 재실행.
  5. 토큰 재발급 후 재연결.
- 완료 기준:
  - 기능 이상 없음.
  - 로그 과다 출력 없음.
  - 재접속 정책이 코드/로그에서 일관되게 확인됨.

## 5. 단계 게이트(진행 조건)
- Gate A: Step 1 완료 + 빌드 성공.
- Gate B: Step 2 완료 + `2002` 루프 차단 로그 확인.
- Gate C: Step 3 완료 + 장애 복구 백오프 확인.
- Gate D: Step 4 완료 + 로그량 기준 충족.
- Gate E: Step 5~6 완료 + 운영 시나리오 통과.

## 6. 유의사항
- `2002` 의미를 서버 정책과 사전 확정한다(세션 TTL, 중복 판정 기준).
- 쿨다운 상태가 영구 고착되지 않도록 성공/재시작 시 초기화한다.
- 동시 재연결 요청을 단일화한다(`isConnecting` + 상태머신).
- 운영자가 즉시 판단할 수 있는 사용자 메시지를 유지한다.

## 7. 변경 추적 규칙
- 각 단계마다:
  1. 변경 파일 목록
  2. 핵심 diff 요약
  3. 실행한 검증 명령
  4. 결과 로그 샘플
- 위 4개를 남기고 다음 단계로 진행한다.
