## 1. 목적과 적용 범위

운영 서버에 접속하지 않고 계류대 배치, 색상, 글자, 경매 화면을 확인할 수 있는 별도 WPF 점검 프로그램을 만든다. 현재 프로그램의 실제 View와 표시 ViewModel을 재사용하여 점검 화면과 운영 화면의 차이를 줄인다.

지원 해상도는 **128×64, 128×128, 160×64, 320×64**다. 네 가지 크기의 번호·색상 점검을 지원하고, 경매 화면은 해당 해상도·사업장에서 실제 구현된 화면만 제공한다.

| 기능 | 계획 |
| --- | --- |
| 계류대 번호 | Board.XML의 행·열·계류대 배치를 표시하고 슬롯별 번호 확인 |
| 색상 | 빨강·초록·파랑·흰색·검정 단색 출력 |
| 밝기 | 단색 패턴의 RGB 출력 강도를 0~255로 조절 |
| 경매 화면 | 진행 페이지·유전능력 페이지·낙찰·유찰 수동 선택 |
| 자동 순환 | 사용 가능한 화면 목록을 지정한 간격으로 순환 |
| 해상도·사업장 | 읽어 온 설정을 기본값으로 사용하고 점검 중 메모리에서 변경 |
| 표시 데이터 | 일반 값·긴 이름·빈 값 등을 선택할 수 있는 가상 데이터 |

밝기 조절은 **화면 픽셀의 색 강도 조절**이다. 전광판 제어기의 하드웨어 밝기를 설정하는 기능으로 표시하지 않는다. 밝기 변경은 단색 점검 모드에만 적용한다.

## 2. 참고 코드에서 확인한 보완 사항

| 현재 참고 도구 | 이관 방향 |
| --- | --- |
| .NET 9 빌드 폴더의 제품 DLL을 직접 참조 | 현재 제품과 같은 .NET 10 WPF 및 ProjectReference 사용 |
| 패널 크기와 배치 높이가 128×128 고정 | 선택 해상도의 폭·높이를 모든 배치 계산에 적용 |
| MockPanelViewModel에 과거 표시 규칙 중복 | 현재 표시 ViewModel에 가상 경매품을 전달 |
| 실제 화면 위에 별도 비고 TextBlock 추가 | 현재 공통 비고 호스트·바인딩 재사용 |
| 제품 네임스페이스에 빈 대체 클래스 선언 | 대체 클래스는 가져오지 않고 실제 의존성을 정리 |
| 계류대 번호를 Dictionary의 고유 키로 사용 | 물리 슬롯의 행·열 또는 고유 인덱스를 키로 사용 |
| 순환할 때마다 users.XML 재조회 | 설정 스냅샷을 사용하고 설정 변경 시에만 목록 재계산 |
| 운영 XML 복사·제품 실행·NamedPipe 기능 포함 | 첫 구현은 독립 점검에 집중하고 자동 운영 실행·외부 제어는 제외 |

계류대 번호가 중복되어도 각 물리 슬롯이 누락되지 않아야 한다. 설정 오류와 지원하지 않는 크기는 사용자에게 표시하고 임의로 128×64 화면으로 대체하지 않는다.

## 3. 현재 화면 지원 범위

화면 선택 기준은 [DisplaySelect](../../../Presentation/Display/DisplaySelect.cs)와 [SetCustomDisplay](../../../Presentation/Display/SetCustomDisplay.cs)에 있다. 페이지 번호를 곧바로 ‘유전능력’ 같은 고정 역할로 가정하지 않는다.

| 해상도 | 현재 선택 구조 | 점검 도구 처리 |
| --- | --- | --- |
| 128×64 | 최대 4개 진행 페이지, 특정 사업장은 페이지 순서가 다름 | 실제 순서와 결과 화면 사용 |
| 128×128 | 진행 1·2페이지와 특정 사업장의 3페이지, 조합별 결과 화면 | 사업장·설정별 실제 페이지와 공통 비고 호스트 사용 |
| 160×64 | 진행 1·2페이지와 결과 화면 | 실제 선택 결과를 기준으로 제공 |
| 320×64 | 진행 1·2페이지 및 결과 화면 선택 경로가 있으나 일부 XAML은 빈 틀 | 구현 여부를 조사해 빈 틀은 ‘미구현’으로 안내하고 순환에서 제외 |

첫 단계에서 각 화면의 실제 내용까지 확인하여 지원표를 확정한다. View 객체가 생성된다는 이유만으로 점검 가능한 화면으로 판정하지 않는다. 미구현 운영 화면을 새로 만드는 작업은 이번 이관 범위에 포함하지 않는다.

## 4. 구조와 재사용 원칙

### 4.1 독립 실행 프로젝트

- `Tools/GAMSTest/`에 별도 실행 프로젝트를 둔다.
- 제품 프로젝트를 ProjectReference로 참조하고, 특정 Debug DLL 경로에 의존하지 않는다.
- 루트 제품 프로젝트의 기본 파일 수집에서 도구의 C#·XAML·리소스 및 생성물이 중복 포함되지 않도록 제외 항목을 설정한다.
- 도구 자체 Application으로 시작한다. 제품 App 또는 MainWindow를 생성하지 않는다.
- 현재 공유 스타일과 동적 색상 리소스를 사용한다. 필요하면 색상 리소스 초기화 부분만 공통화한다.
- 제품 게시물에 점검 도구가 의도치 않게 포함되지 않도록 빌드·게시 범위를 구분한다.

### 4.2 화면 생성과 운영 제어 분리

현재 DisplaySelect는 화면 선택뿐 아니라 UDP 페이지 동기화와 회전 타이머도 관리한다. 따라서 점검 도구에서 그대로 생성하면 불필요한 운영 기능이 시작될 수 있다.

- 통신을 시작하지 않는 화면 생성·지원 목록 부분을 공통 팩터리로 추출한다.
- 제품 DisplaySelect와 점검 도구가 동일한 선택 함수를 사용하도록 한다.
- 기존 사업장 분기, 페이지 순서, 뿌리농가·품목 조건, 공통 비고 호스트 적용 조건을 유지한다.
- 제품의 MASTER/SUB 동작과 경매 신호에 따른 회전 정책은 변경하지 않는다.
- AuctionContPanelViewModel의 운영 제어 객체 의존성을 점검하고, 화면 표시만 생성할 수 있도록 필요한 최소 생성 경로를 제공한다. 가짜 클래스나 null 강제 주입으로 우회하지 않는다.
- 진행·결과 화면의 DataContext 차이를 실제 바인딩에 맞게 연결하고 현재 AuctionItemDisplayViewModel의 표시 규칙을 재사용한다.

### 4.3 설정과 데이터

- Board.XML의 배치·해상도와 users.XML의 화면 선택·색상 설정을 읽기 전용으로 가져온다.
- 설정 파일이 없어도 기본 가상 배치로 시작할 수 있게 한다.
- 해상도·사업장·표시 옵션 변경은 도구의 메모리 상태에만 반영한다. 운영 XML을 덮어쓰지 않는다.
- 실제 users.XML을 도구의 배포 예제로 자동 복사하지 않는다. 필요한 표시 항목만 있는 가상 예제를 제공한다.
- 로그인, Netty, HTTP API, UDP 동기화, 운영 SQLite 접근을 시작하지 않는다.
- 이력 페이지도 가상 주소·이력 데이터로 확인한다. 실운영 API 응답이나 개인정보를 샘플로 저장하지 않는다.

## 5. 사용 흐름과 렌더링

1. 점검 도구를 실행하고 설정을 읽거나 기본 배치를 선택한다.
2. 제어창에서 해상도·사업장·배치를 확인한다. 표시창에는 계류대 번호가 나타난다.
3. 단색 패턴과 밝기를 확인한다.
4. 해당 조건에서 가능한 경매 화면을 선택해 실제 글자·배치를 확인한다.
5. 필요하면 가상 데이터 유형과 순환 간격을 선택하고 자동 순환한다.
6. 종료 시 타이머·이벤트·화면 자원을 정리한다.

제어창과 표시창을 분리하고, 표시창의 위치와 크기를 확인할 수 있게 한다. 원래 크기 출력과 확대 미리보기를 구분한다. WPF의 논리 단위와 Windows DPI 배율이 물리 픽셀과 같다고 가정하지 않으며, 실제 출력 배율은 장비에서 검증한다.

사용자가 중요하게 보는 100~200개 전광판의 도미노 현상을 고려하여 다음 기준을 적용한다.

- 화면은 필요 시 준비하고 재사용한다. 매 순환마다 모든 View를 새로 생성하지 않는다.
- 모든 슬롯은 하나의 순환 타이머와 동일한 목표 페이지를 사용한다.
- WPF 컨트롤 생성과 바인딩 변경은 UI 스레드에서 수행한다. 별도 스레드에서 View를 만들어 붙이지 않는다.
- 수동 화면·번호·색상 선택은 자동 순환을 중지한다.
- 해상도나 사업장 변경 시 이전 화면 캐시와 이벤트를 해제한다.
- 숨김·반복 진입·창 종료 시 타이머와 애니메이션 수명을 확인한다. 운영 화면 전체의 애니메이션 최적화로 범위를 확대하지 않는다.
- 준비 시간과 전환 지연은 별도로 측정한다. 도구에서의 동시 전환을 실제 장비 전체의 동시 출력 보장으로 표현하지 않는다.

## 6. 단계별 구현과 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1. 지원 범위 확정 | 해상도·사업장·진행/결과 화면·비고 호스트 대조 | 빈 화면과 지원 페이지를 구분한 목록 작성 |
| 2. 공통 생성 경로 | 화면 팩터리와 표시 전용 ViewModel 생성 경로 정리 | 제품의 기존 선택 결과·페이지 순서가 유지되고 통신 없이 화면 생성 가능 |
| 3. 점검 기본 기능 | 별도 프로젝트, 설정 읽기, 번호·RGB·흰색·검정·밝기 | 네 해상도에서 배치와 슬롯 수가 일치하고 운영 설정 미변경 |
| 4. 실제 화면 연결 | 우선 128×128을 연결한 뒤 나머지 세 해상도 적용 | 실제 View·표시 규칙 재사용, 지원하지 않는 화면은 명시적으로 안내 |
| 5. 순환·수명 관리 | 단일 타이머, 화면 재사용, 반복 변경·종료 처리 | 중복 순환·이벤트 누적 없이 100/200 슬롯 점검 가능 |
| 6. 검증·문서화 | 자동 검사, 화면 확인, 사용법·구현 결과 기록 | 아래 검증 결과 및 장비에서 남은 확인 사항 기록 |

단계는 구현 순서이며, 전체 요청 완료는 네 해상도에 대한 약속한 범위가 충족된 때로 본다. 128×128 구현만으로 전체 이관 완료를 표시하지 않는다.

## 8. 검증 계획

- 제품과 도구를 Debug·Release로 빌드한다. 게시 확인이 필요하면 기존 배포본과 분리된 임시 경로를 사용한다.
- 기존 오프라인 검증 도구 중 화면 선택·페이지·바인딩 관련 검사를 실행한다. 실제 실행 명령과 결과는 구현 기록에 남긴다.
- 공통 팩터리 추출 전후 대표 사업장·품목·해상도의 View 유형과 페이지 순서를 비교한다.
- 번호·색상 패턴은 네 해상도 모두에서 폭·높이·행·열·전체 슬롯 수를 확인한다. 중복 계류대 번호도 포함한다.
- 가상 데이터로 긴 출하주·낙찰자 이름, 이름/번호/이름+번호, 빈 값, 가격 쉼표, 개체번호 강조, 세 글자 성별, 비고와 이력 문구를 확인한다.
- 낙찰·유찰·진행 전환 및 공통 비고가 중복 표출되지 않는지 확인한다.
- 설정 파일 누락·잘못된 XML·지원하지 않는 해상도에 대해 오류 안내와 복구 동작을 확인한다.
