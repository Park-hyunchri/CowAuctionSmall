## 1. 변경 목표와 보존 기준

성별 스타일을 결정하기 위해 경매품 전체를 복제하는 처리를 제거하고, 반복 생성되는 Style 및 화면 요소를 XAML 리소스와 화면 구성으로 옮긴다. 이와 함께 성별 표시 영역의 두 글자 폭 안에서 다음 규칙을 적용한다.

| 입력 문구 | 화면 문구 | 표시 방식 |
| --- | --- | --- |
| `암`, `수` 등 1글자 | 그대로 | 기존 크기·배치 유지 |
| `거세`, `비육`, `암소`, `숫소`, `공통`, `새끼` 등 2글자 | 그대로 | 기존 두 글자 표시 방식 유지 |
| `비거세`, `미경산` 등 3글자 성별 | 그대로 | 두 글자로 자르지 않고 글자 가로 폭만 압축 |
| `프리마틴` | `프리` | 명시적으로 두 글자로 표시 |

3글자의 가로 배율은 약 `2/3`(67%)를 최초 검토값으로 삼는다. 해상도별 실제 글꼴과 테두리 안쪽 여유를 측정하여 조정하며, 모든 화면에 67%를 고정 적용하지 않는다. 추가 압축은 가로에만 적용하고 해당 화면의 기준 글자 높이는 유지한다.

4글자 이상인 임의의 문구를 앞 두 글자로 자르는 일반 규칙은 만들지 않는다. 이번에 명시적으로 줄이는 문구는 `프리마틴`이다. 기존 입력이 이미 `프`, `프리`, `거`, `비거`, `새`인 경우에는 원래 긴 이름을 추정해 복원하지 않고 해당 입력과 사업장 예외를 유지한다.

다음 항목은 변경하지 않는다.

- 원본 성별 데이터: 표시용 축약이나 배율을 `gValues.Sex`에 다시 저장하지 않는다. 원본과 표시 문구를 구분한다.
- 파서의 `ChangeSexName` 처리, 품목에 따른 성별 문구 변환, 횡성의 월령·품목별 예외.
- 예천 화면의 특정 문구 숨김 조건은 유지한다. 앞 두 글자를 잘라 쓰던 성별 표시에는 위의 새 규칙을 적용한다.
- 색상, 굵기, 글꼴과 기준 높이, 외곽선·테두리의 모양, 성별 표시 영역의 위치와 두 글자 폭. 표시 문구 변경과 가로 압축에 직접 필요한 조정만 허용한다.
- 화면별 `Margin`, `RenderTransform`, `Width`, `Canvas.Left/Top`, `Panel.ZIndex` 등의 기존 역할과 우선순위. 가로 압축을 추가할 때 위치 이동을 잃거나 기존 압축과 중복 적용하지 않는다.
- 앞서 완료한 가격·중량·임신 표시 이관, NOTE·추가 이력 표시와 스크롤 동작.

성별의 업무상 재분류는 이번 작업에 포함하지 않는다. `암`과 `암소`, `수`와 `숫소`를 같은 스타일로 강제 통합하지 않는다. 색상은 새 표시 문구가 아닌 원본 성별의 스타일 기준으로 결정한다. 따라서 원본이 `프리마틴`인 항목을 `프리`로 표시해도 해당 화면의 프리마틴 색상을 유지한다.

## 2. 현재 구조와 확인한 비용

```text
API / SV 수신
  → AnimalParseData의 기존 성별 문구 결정
  → gValues.Sex
  → Text 바인딩 + 성별 Converter
  → 해상도·사업장별 스타일 또는 화면 요소
```

| 클래스 | 활성 바인딩 수 | 현재 역할·특징 |
| --- | ---: | --- |
| `CowTypeToStyleConverter_128_64` | 3 | 성별에 따라 글자 크기·색상·여백·ScaleTransform 결정. 변환할 때마다 Style과 Setter 생성 |
| `CowTypeToStyleConverter_160_64` | 5 | 위와 같은 구조이며 위치·압축 비율과 긴 문구 처리 값이 다름 |
| `CowTypeToStyleConverter_V3` | 31 | 성별·축약어를 Style에 매핑. 이미 정적 Style과 브러시를 재사용 |
| `CowTypeToStyleConverter_OutLine_V3` | 2 | 예천 진행·유찰에서 성별과 등록구분을 받아 Grid·Border·OutlinedTextBlock 또는 TextBlock을 생성 |

총 41개 활성 바인딩을 확인했다. 주석 안의 예전 코드는 제외했으며, 클래스 이름과 다른 리소스 키로 사용되는 경우도 포함했다. 구현 시작 시 다시 확인한다.

추가로 성별 스타일 바인딩 15곳이 `CopyGValues`를 사용한다. 이 속성은 getter에서 `Clone()`을 호출하므로 성별 스타일을 읽을 때 경매품 전체를 복제한다. 화면 갱신 경계에서 필요한 스냅샷 복제와 이 추가 복제는 구분해야 한다.

일부 구현의 주요 차이:

- V3는 `프`, `거`, `비거`, `프리`, `새`를 별도로 처리한다. 다른 프로필에 이 대응을 새로 추가하면 현재 색상·크기가 바뀔 수 있다.
- V3의 알 수 없는 성별 기본 색상은 검정이고, 다른 구현에는 분홍 계열 기본값이 있다. 기본값을 일괄 통일하지 않는다.
- `수`의 색상도 V3와 소형 해상도에서 다르다. 같은 의미라는 이유로 색상을 합치지 않는다.
- XAML의 로컬 속성이 Converter가 만든 Style 값을 덮어쓰는 화면이 있다. Converter의 설정표만 비교하면 실제 화면 차이를 놓칠 수 있다.

## 3. 목표 구조

```text
기존 파서 → 기존 gValues.Sex
  → AuctionItemDisplayViewModel의 성별 표시 값
  → XAML Style·Trigger / 예천 성별 표시 영역
```

### 3.1 공통 표시 ViewModel

이미 도입한 `AuctionItemDisplayViewModel`을 확장한다. 별도의 성별 전용 데이터 복제 계층은 만들지 않는다.

| 표시 속성 예시 | 책임 |
| --- | --- |
| `SexText` | 3글자는 원문 유지, `프리마틴`만 `프리`로 바꾸는 공통 표시 문구 |
| `SexStyleKey` | `Snapshot.Sex`를 기준으로 선택하는 스타일 분류. 축약된 표시 문구 때문에 색상 분류가 달라지지 않도록 분리 |
| `OutlinedSexText` | 공통 표시 문구에 예천의 기존 숨김 조건만 반영한 결과. 별도의 앞 두 글자 자르기는 제거 |
| `SexPresentationMode` | 예천의 일반·혈통·일치 표시 분기. enum 등 명확한 값으로 표현 |
| 필요한 글자 길이 구분 | 표시 문구가 1·2·3글자인지 구분하여 두 글자 폭과 가로 압축을 선택할 데이터 제공 |

위 이름은 제안이며 구현 시 실제 사용에 맞춰 최소 속성으로 확정한다. 사용하지 않는 성별별 bool 속성을 나열하지 않는다.

- `SexText`에는 합의한 `프리마틴 → 프리` 외의 새로운 Trim·축약·치환을 적용하지 않는다. 이미 파서가 선택한 문구에 품목·월령 변환을 다시 적용하지 않는다.
- `Brush`, `Style`, `Thickness`, 화면 요소를 ViewModel에서 생성하지 않는다.
- 동일 데이터 재수신은 기존 동등 비교로 걸러 공통 표시 객체를 재사용한다.
- 성별 또는 등록구분 변경 시 기존 스냅샷 교체 흐름에서 표시 값을 다시 계산한다. 가격만 바뀐 경우에도 화면 요소 전체를 Converter에서 다시 생성하는 경로는 없앤다.
- Running은 기존 `ItemDisplay`, Sold·UnSold는 공통 표시 ViewModel을 사용한다. 이미 이관한 가격·중량·임신 표시와 같은 갱신 경계를 따른다.

### 3.2 일반 성별 스타일

공통 XAML 리소스 사전에 해상도별 스타일을 정의하고, 각 View는 자신의 기존 프로필을 선택한다.

- 128×64, 160×64, V3를 서로 다른 스타일 키로 유지한다.
- 공통으로 동일한 설정만 재사용한다. 모든 화면을 하나의 크기·색상·여백으로 합치지 않는다.
- 원본 성별의 스타일 분류에 따른 선택은 XAML DataTrigger로 처리한다. 표시 문구나 별칭을 원본에 덮어쓰지 않는다.
- 3글자 표시에는 두 글자 영역 안에서 가로 압축을 적용한다. 세로까지 줄이는 일괄 Viewbox 축소는 사용하지 않는다. `프리`로 표시하는 항목에는 3글자 또는 기존 4글자용 압축이 남지 않도록 한다.
- 기존 ScaleTransform과 새 압축을 곱해 과도하게 좁아지지 않도록 프로필별 최종 변환을 정한다. TranslateTransform의 위치 이동, 정렬 기준과 테두리는 별도로 유지한다.
- 성별 표시 영역만 공통 표시 ViewModel에 연결한다. 필요한 경우 기존처럼 루트 ViewModel을 명시적으로 참조한다. 관련 없는 화면 전체의 DataContext는 바꾸지 않는다.
- 기존 로컬 속성과 Style 설정의 우선순위를 보존한다. 암묵적 TextBlock 스타일을 무조건 `BasedOn`으로 추가하여 렌더링 옵션이나 동작을 바꾸지 않는다.
- 읽기 전용 표시 속성의 바인딩은 `Mode=OneWay`로 명시한다.

### 3.3 예천의 외곽선·테두리 표시

현재 두 화면에서 동일한 Converter를 사용하는 부분을 공통 XAML 표시 영역으로 옮긴다. 필요하면 `Views/Common`의 작은 UserControl로 공유하되 새로운 업무 로직은 code-behind에 넣지 않는다.

| 현재 분기 | 새 문구 규칙과 보존할 모양 |
| --- | --- |
| 등록구분 `혈통` | `비거세`·`미경산`은 원문과 가로 압축, `프리마틴`은 `프리` 적용. 원본 성별별 색상·위치, 테두리 두께 2, 모서리 반경 4, ExtraBold 및 외곽선 두께 1 유지 |
| 등록구분 `일치` | 같은 길이별 표시 규칙 적용. 글자 크기 14, Regular, 테두리 두께 1, 모서리 반경 3, 외곽선 두께 0.2 및 이 분기의 기존 색상·위치 유지 |
| 나머지 | 공통 표시 문구와 가로 압축 적용. 원본 문자열 길이가 2보다 크고 `정보없음` 또는 `일치`가 포함된 경우는 기존처럼 빈 문구 표시 |

3글자는 테두리를 세 글자 폭으로 넓히지 않고 기존 두 글자 영역 안에 넣는다. 테두리 전체를 압축하여 선 두께나 모서리를 찌그러뜨리지 않고 글자 부분의 가로 폭만 조절한다. 글자와 외곽선이 테두리 안에서 잘리지 않는지 확인한다. 한 글자와 빈 문자열의 테두리 동작은 별도로 기존 기준과 비교한다.

일반·혈통·일치 분기의 시각 요소를 XAML에서 만들고 표시 상태를 전환한다. Converter가 바인딩 평가마다 새 Grid와 자식 컨트롤을 반환하는 방식은 제거한다. UIElement 자체를 여러 화면이 공유하도록 캐시하지 않는다. 재사용 대상은 스타일·브러시 등 리소스이며 화면 요소는 각 View가 소유한다.

## 4. 단계별 변경 순서

| 단계 | 변경 내용 | 완료 기준 |
| --- | --- | --- |
| 1. 기준 확보 | 41개 사용처, 15개 복제 바인딩, 실제 스타일과 두 글자 영역의 안쪽 폭·기준 높이·기존 압축을 기록 | 보존할 모양과 의도적으로 바꿀 축약·압축 결과를 구분함 |
| 2. 표시 값 연결 | 공통 문구, 원본 기반 스타일 분류, 예천 분기 값을 추가. 원본 파서와 변환 규칙은 유지 | 3글자 원문·프리마틴 축약 규칙을 만족하고 성별·등록구분 변경이 전달됨 |
| 3. 일반 스타일 이관 | 프로필별 XAML 스타일로 전환하고 두 글자 폭에 맞는 가로 압축 적용. 전체 객체 바인딩 제거 | 원본별 색상과 기준 높이·위치는 유지되며 긴 문구가 잘리지 않고 추가 Clone이 없음 |
| 4. 예천 표시 이관 | 공통 XAML 표시 영역으로 교체하고 일괄 두 글자 자르기를 제거 | 새 문구 규칙과 기존 분기·숨김 조건을 만족하며 테두리 안에서 3글자가 표시됨 |
| 5. 잔여 참조 정리 | 대체 완료한 성별 Converter 4개와 해당 리소스 선언 제거. CopyGValues 전체 참조 확인 | 활성 XAML·C# 참조가 없고 불필요한 변환 경로가 제거됨 |
| 6. 회귀 검증 | 상태 전환·새로고침·각 해상도·주요 성별 값·예천 분기 검증과 빌드 | 결과·미확인 항목을 보고하고 구현 완료 후 WORKLOG에 기록 |

`CopyGValues` 속성 자체는 성별 외 사용처가 없는 것을 최종 확인한 경우에만 제거한다. `Clone()`, 모델의 동등 비교, 화면 갱신 경계의 스냅샷 복제는 유지한다.

기존 `SexDisc`의 정리, 다른 Converter의 이관, 동적 색상 설정 기능 추가, Storyboard 개선은 이번 작업에 포함하지 않는다.

## 6. 검증 계획

### 새 표시 규칙과 기존 모양 검증

- 모든 프로필에서 1·2글자 성별의 기존 표시를 비교한다. `비거세`·`미경산`은 세 글자가 모두 보이고, `프리마틴`은 정확히 `프리`로 보이는지 확인한다.
- `프`, `거`, `비거`, `프리`, `새`, `-`, 빈 값, 미등록 문자열과 공백 포함 문자열을 비교한다. 표시 문구를 임의 보정하지 않는다.
- null·바인딩 미설정은 오류 없이 처리하는지 별도로 확인하고, 유효 데이터의 기존 표시를 바꾸는 근거로 사용하지 않는다.
- 횡성 등 파서에서 만들어진 문구에 품목·월령 규칙이 재적용되지 않는지 확인한다. 기존 `프` 같은 입력을 임의로 `프리`로 바꾸지 않는다.
- 예천의 등록구분 `혈통`, `일치`, 기타와 길이 0·1·2·3 및 `프리마틴` 조합을 확인한다. 기존 숨김 조건도 포함한다.
- `프리마틴 → 프리` 전환 후 원본 성별에 해당하는 색상이 유지되는지 확인한다. `일치` 분기의 별도 색상도 보존한다.
- 3글자는 두 글자 영역을 넘지 않고, 가로만 압축되어 기준 높이가 유지되는지 확인한다. 67%는 고정 정답으로 검사하지 않고 실제 글꼴·여백에 맞춘 최종 배율과 가독성을 확인한다.
- 실제 적용된 글꼴·색상·굵기·높이·Margin·정렬·최종 변환·테두리·외곽선을 확인한다. 리소스 선언뿐 아니라 잘림·겹침과 압축 중복 여부를 검사한다.
- 화면별 로컬 Margin·TranslateTransform과 암묵적/명시적 Style의 우선순위가 바뀌지 않았는지 확인한다.

### 갱신·수명 주기

- 새로고침으로 `암 → 수`, `거세 → 비거세 → 암`, `미경산 → 프리마틴 → 수`가 바뀔 때 문구·스타일·배율이 함께 갱신되고 이전 가로 압축이 남지 않는지 확인한다.
- 성별은 같고 등록구분만 바뀌는 경우 예천 분기가 갱신되는지 확인한다.
- 같은 데이터 재수신, 가격만 변경, 다른 경매품으로 교체, 진행·낙찰·유찰 전환, 반복 로드·해제를 확인한다.
- 예천에서 같은 분기의 데이터 갱신 시 시각 요소가 불필요하게 재생성되지 않는지 확인하고, 여러 패널에 같은 요소가 연결되는 부모 충돌이 없는지 확인한다.
- 기존 가격·중량·임신, 개체번호 강조, NOTE·이력과 스크롤 회귀를 확인한다.

### 실행 방법과 성능 판단

- 기존 `ReferenceAdoptionChecks`의 `binding` 검사를 활용한다. 보존할 스타일은 기존 기대값과 비교하고, 3글자 원문 표시와 `프리마틴 → 프리`는 변경된 규칙에 맞는 기대값으로 검증한다.
- 비고 공통 호스트의 연결에 영향이 있으면 `OwnerHistoryChecks --scroll-offline`을 실행한다.
- 구현 후 별도 임시 출력 경로로 Debug·Release 빌드와 필요한 오프라인 검증을 수행한다. 복원 자산이 유효하면 `--no-restore`를 사용한다.
- 화면 비교는 운영 데이터 대신 합성 데이터와 동일한 글꼴·배율·해상도를 사용한다. 실제 전광판 육안 확인 결과와 자동 검증 결과를 구분한다.
- 기대 효과는 추가 경매품 복제 제거와 반복 Style·컨트롤 생성 감소다. V3는 이미 정적 Style을 재사용하므로 전체 경로가 같은 폭으로 빨라진다고 가정하지 않는다.
- XAML Trigger·바인딩에도 비용이 있으므로 개선율은 필요 시 동일한 입력·패널 수로 전후 할당량과 갱신 시간을 측정한 뒤 보고한다. Converter 삭제 개수만으로 성능을 판단하지 않는다.

- `SexDisplayStyles.xaml`을 App에 등록하고 128×64·160×64·V3 프로필을 분리했다. 화순 유찰 2곳·상주 유찰 1곳은 기존에 문자열을 객체용 Converter에 전달해 검정 기본 스타일을 사용하고 있었으므로, 이번에도 `SexTextV3Fallback`으로 그 결과를 보존했다. 색상 정책 수정은 별도 작업이다.

- 횡성은 Display 모드의 실제 3글자 폭 72픽셀을 기존 46픽셀 영역에 맞춰 `46/72`(약 64%)로 압축한다. 기존 세로 위치 이동은 유지한다.
