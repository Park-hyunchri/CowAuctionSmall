# 코드리뷰 이슈 리스트 (2026-02-14)

## 리뷰 범위
- `Services/`
- `NetProto/netty/`
- `ViewModels/`

## 이슈 리스트 (심각도순)
1. [Critical] 연결 실패 시 `NotImplementedException` 발생
위치: `NetProto/netty/NettyControllable.cs:62`, `NetProto/netty/AuctionShareNettyClient.cs:202`
영향: 실제 네트워크 오류 상황에서 예외가 다시 터지며 정상 복구 흐름이 끊길 수 있음.
권장 조치: `onConnectionException()`에서 예외 throw 대신 상태 알림/로그 처리로 전환.

2. [High] 비활성 Netty 클라이언트 정리 누락
위치: `NetProto/netty/AuctionDelegate.cs:45`
영향: 비활성 상태(`!isActive`)일 때 `stopClient()`가 호출되지 않아 리소스가 누적될 수 있음.
권장 조치: `mClient != null`이면 활성 여부와 무관하게 정리 루틴을 실행하고 `mClient = null` 보장.

3. [High] 앱 종료 경로에서 서비스 dispose 미호출
위치: `App.xaml.cs:113`, `Services/ServerGetData.cs:963`
영향: 종료 후 즉시 재실행 시 유령 세션/중복접속(2002) 확률 증가.
권장 조치: `OnExit`에서 `ServerGetData` 및 Netty 자원 정리 호출을 명시적으로 보장.

4. [High] `AS` 메시지 분기 조건 우선순위 버그
위치: `Services/NettyAsyncMsgProcess.cs:168`
영향: 데이터 길이 검증 없이 인덱스 접근이 발생할 수 있어 런타임 예외 위험 존재.
권장 조치: 조건식을 괄호로 분리해 길이 검증을 `PROGRESS/COMPLETED` 모두에 강제 적용.

5. [High] `async void` 사용으로 예외 추적/제어 불가
위치: `Services/NettyAsyncMsgProcess.cs:260`
영향: 비동기 예외가 호출 체인으로 전파되지 않아 장애 분석과 복구 제어가 어려움.
권장 조치: `Task` 반환 메서드로 변경하고 호출부에서 await 또는 안전한 fire-and-forget 래퍼 사용.

6. [Medium] Messenger 구독 해제 누락
위치: `Services/ServerGetData.cs:81`, `Services/ServerGetData.cs:84`, `Services/ServerGetData.cs:963`
영향: 종료/재시작 반복 시 중복 콜백 및 메모리 누수 가능성.
권장 조치: 등록한 메시지 채널을 dispose에서 동일하게 모두 해제.

7. [Medium] Finalizer에서 블로킹 대기 사용
위치: `Services/ServerGetData.cs:965`, `Services/ServerGetData.cs:975`
영향: Finalizer 스레드 정체 및 예외 리스크 증가.
권장 조치: 표준 dispose 패턴으로 분리하고 finalizer에서는 관리 리소스 작업을 수행하지 않도록 정리.

8. [Medium] API 호출마다 `HttpClient` 신규 생성 및 인증서 검증 우회
위치: `Services/ServerConn.cs:250`, `Services/ServerConn.cs:255`
영향: 성능 저하/소켓 관리 비효율 + 보안 취약점 가능성.
권장 조치: DI로 주입된 `HttpClient` 재사용, 인증서 정책은 환경별로 분리.

9. [Low] 로깅 오탈자로 로그 누락
위치: `Services/ServerGetData.cs:933`, `Views/MainWindow.xaml.cs:78`
영향: 장애 상황에서 핵심 로그가 남지 않아 원인 추적 지연.
권장 조치: `logger.Equals(...)`를 실제 로깅 메서드(`LogInfo`/`LogError`)로 교체.
