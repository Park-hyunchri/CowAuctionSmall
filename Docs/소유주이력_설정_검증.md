## 적용된 동작

- 비고 색상: 일반 Note와 구분자 ` / `는 빨간색(Red), NoteChangeOwner는 흰색(White)이다. 기존 비고가 비어 있거나 `-`이면 흰색 이력만 표시한다. 이력 미사용 시 빨간색 원래 비고만 남는다.
- 비고 XAML 13곳은 `Views/Common/NoteText.cs`의 Normal·History 연결 속성으로 한 TextBlock 안의 Run을 구성한다. 합성 텍스트와 전체 폭은 기존 스크롤에서 그대로 사용한다. 색상·화면 상태·대표 4개 해상도 검증을 포함해 총 130개 검증이 통과했다.

- 2026-09-15 스크롤 보완: 128×128 진행·낙찰·유찰 공통 비고에서 같은 개체·같은 문구는 페이지 전환이나 데이터 객체 교체에도 스크롤을 유지한다. 문구가 바뀌거나 다른 개체가 표시되면 다시 시작한다. Unloaded 시 애니메이션과 대기 중 초기화 작업을 해제한다.
- 추가 검증: 실제 WPF 애니메이션으로 페이지 반복 전환·문구 끝부분 도달·같은 개체 갱신·문구 변경·개체 교체·화면 재진입·종료를 16개 항목으로 확인했다. 기존 91개와 합쳐 총 107개 통과. 실제 Debug 앱에서도 같은 문구가 끝까지 이동한 뒤 반복하는 것을 확인했다.

- 로그인 후 표시하는 소의 원본 15자리 `TraceNumber`로 옵션 2를 조회한다. 염소 등 다른 축종에는 요청하지 않는다.
- `AnimalHistoryParser`가 XML을 해석하고 `AnimalHistoryNoteFormatter`가 최근 소유주 변경 한 건을 구성한다. 예: `이전 소유주 → 현재 소유주(양수 YYYY-MM-DD)`.
- 기존 `Note`는 보존한다. 이력은 `NoteChangeOwner`, 화면 합성은 `DisplayNote`가 담당한다. 기존 비고가 비어 있거나 `-`이면 이력만 표시한다.
- 최초 등록만 있거나 변경 순서를 확정할 수 없는 이력은 변경 문구를 만들지 않는다. 정상 조회 결과가 0건인 경우도 당일 캐시에 저장한다.
- 같은 개체의 동시 요청을 합치고 정상 결과를 당일 재사용한다. 경매 화면은 이력 응답을 기다리지 않는다. 새 응답이 와도 원래 비고를 중복 연결하지 않는다.
- 화면에서 사라진 개체의 SQLite 이력도 당일까지 보관한다. DB 행은 삭제하지 않는다. 2026-09-23부터 현재 대상에서 빠지고 다른 소비자도 없는 미완료 요청은 취소하며, 겹치는 대상과 다른 소비자가 기다리는 요청은 재사용한다.
- 응답은 현재 화면의 원본 개체번호·조회 세대·날짜가 일치할 때만 반영한다. 캐시 결과도 임시 준비한 뒤 전체 처리 완료 시 일괄 반영한다. 먼저 조회된 개체만 중간에 추가 표시하지 않는다.
- 하단의 이력 상태줄에서 캐시 확인, 처리 수/전체 수, 캐시·성공·실패·중단, 반영 대기·완료를 확인한다. 정상 빈 결과도 성공 건수에 포함하며, 실제 문구가 있는 건수는 별도로 안내한다. 경매 신호·일반 로그와 분리된다.
- 하단 상태창을 우클릭하여 **표시 중인 소유주 이력 새로고침**을 실행할 수 있다. 성공 뒤 1분 이내 재요청을 제한하고 오류 뒤에는 5분간 재시도를 억제한다.
- 일시 통신 오류는 최초 요청을 포함하여 최대 3회 시도한다. 인증 오류·한도 초과는 당일 중단 상태를 DB에 보존한다. 실패한 새 응답으로 기존 정상 이력을 덮어쓰지 않는다.
- 경매 캐시는 인증 범위·조회 날짜별로 구분한다. 로그인 후 캐시를 표시하고 최신 API 결과를 반영한다. 캐시로 경매 진행 상태를 재개하지 않는다. 정상 빈 응답과 통신 실패를 구분한다.

## XML 설정

`Config/users.XML`과 대체 사업장 XML 7개에 다음 항목을 추가했다. 실제 사용하는 파일에서 수정한 뒤 앱을 재시작한다.

```xml
<AnimalTrace>
  <IsAnimalProductsTraceability>N</IsAnimalProductsTraceability>
  <ServiceKey>발급받은 인증키</ServiceKey>
</AnimalTrace>
```

| 항목 | 의미 |
|---|---|
| IsAnimalProductsTraceability | Y일 때 이력 조회·비고 표시 사용. N·누락·빈 값·잘못된 값은 미사용 |
| ServiceKey | 인증키. 비어 있으면 이력 조회를 사용하지 않음 |

사용자가 현재 users.XML에 추가한 Y를 유지했으며, 대체 XML 7개에는 기본값 N을 추가했다. 이 옵션은 AnimalTrace 하위에 둔다. N이면 자동 조회와 수동 새로고침 모두 API를 호출하지 않고 신규 이력을 저장하지 않는다. 이미 저장된 당일 캐시는 보존하지만 비고에는 원래 Note만 표시한다. 다시 Y로 변경하고 앱을 재시작하면 당일 캐시부터 재사용한다. 이 옵션은 경매 현황 API 호출에는 영향을 주지 않는다. 설정 반영에는 앱 재시작이 필요하다.

나머지는 `Domain/Settings/AnimalTraceSettings.cs`에서 관리한다. 주소는 기존 traceNoSearch, 일일 로컬 제한은 없음(소스 DailyLimit=0), 최소 간격은 1000ms다. `MaxConcurrentRequests`의 기본값은 1이며 구현은 1~4 범위로 제한한다. 제공기관의 동시 호출 허용 조건을 확인하지 못했으므로 운영 기본값은 바꾸지 않았다. 조회 옵션 2와 재시도 정책도 소스에서 관리한다. XML의 Enabled·Address·KeyFile·DailyLimit·RequestIntervalMs·MaxConcurrentRequests는 읽지 않는다.

사용자 요청으로 임의의 하루 100회 제한을 해제했다. 기본 DailyLimit=0은 로컬 일일 상한 없음이다. 기존 100회 집계가 남아 있어도 다음 요청을 허용하며 집계는 계속 기록한다. 공급자의 실제 한도 초과·인증 오류에 따른 당일 중단은 유지한다. 여러 PC의 총 호출 수를 합산하지 않으며, 최소 1초 간격·당일 캐시·중복 요청 공유·재시도 정책은 유지한다.

사용자 요청으로 인증키를 XML의 `AnimalTrace/ServiceKey`에 직접 보관한다. 인코딩된 키도 요청 시 한 번 디코딩한 뒤 인코딩하여 사용한다. 별도 JSON은 더 이상 읽거나 복사하지 않으며 기존 파일은 보존한다. XML은 기존 출력·게시 복사 정책을 따르므로 키도 XML에 포함된다. 키 원문을 로그·문서에 남기지 않는다. 설정 변경 전의 당일 호출 예약량·중단 상태를 유지한다.

## 저장 구조와 초기화

패키지는 `Microsoft.Data.Sqlite 10.0.12`이며 별도 DB 서버 설치 없이 사용한다. DB는 실행 폴더나 OneDrive 대신 다음 위치에 둔다.

```text
%LOCALAPPDATA%\CowAuctionSmall\Cache\<설치 경로 해시>\auction-cache.db
```

테이블은 `daily_cache` 하나다.

| 열 | 용도 |
|---|---|
| cache_type | auction / animal_history / control |
| cache_key | 인증 범위별 경매 키, 원본 개체번호, 호출 제어 키 |
| cache_date | 한국 날짜 yyyy-MM-dd |
| payload_json | 허용된 경매 화면 필드, 필요한 이력 필드 또는 호출 제어 값 |
| created_at / updated_at | 생성·갱신 시각 |

기본키는 `(cache_type, cache_key)`, 스키마 버전은 `user_version=1`이다. API 원본 XML·인증키·농장 상세 주소는 저장하지 않는다. 경매 데이터는 화면에 필요한 명시적 필드만 저장하고, 이력에는 날짜·유형·소유주명만 저장한다.

시작 및 DB 접근 시 오늘과 다른 행이 있으면 전체 행을 삭제한다. 실행 중에는 20초 간격으로 날짜 변경을 확인한다. 메모리 이력도 비우고 이전 날짜 요청의 늦은 응답은 저장·표시하지 않는다. 같은 사용자 계정의 다른 설치본 캐시도 잠겨 있지 않고 알려진 스키마인 경우 만료 데이터를 정리한다.

`secure_delete=ON`, `journal_mode=DELETE`를 적용한다. 앱이 꺼져 있으면 다음 실행 때 삭제하며, 외부 백업·디스크 복구까지 포함한 완전 삭제를 보장하지 않는다. 파일 잠금으로 동일 DB의 중복 사용을 막는다. 잠금·손상·권한·스키마 오류 시 임의로 파일을 덮어쓰지 않고 캐시와 이력 조회를 중단하여 안내한다. 기본 경매 기능은 유지한다.

## 검증 결과와 재실행

가상 데이터와 가짜 HTTP로 **91개** 검증을 통과했다: 기본 48개, 캐시·오류·경합 22개, 실제 WPF 객체·시각 트리 21개. 날짜 변경, 늦은 응답, 중복 요청, 호출 제한, 재시작 캐시, 정상 빈 응답, 저장 필드 제한, 초기 로고, 비고 합성, 패널 갱신, 대표 4개 해상도 및 낙찰·유찰 표시를 포함한다.

```powershell
dotnet build .\CowAuctionSmall.csproj --configuration Debug --no-restore
dotnet build .\CowAuctionSmall.csproj --configuration Release --no-restore
dotnet run --project .\Validation\OwnerHistoryChecks\OwnerHistoryChecks.csproj --configuration Release --no-restore
dotnet publish .\CowAuctionSmall.csproj --configuration Release --runtime win-x64 --self-contained false -p:PublishSingleFile=true --output .\bin\OwnerHistory_Validation_20260915
```

Debug·Release 빌드와 별도 폴더 게시에 성공했다. 최종 게시 빌드는 경고 90개·오류 0개이며 증분 빌드의 경고 0개가 전체 경고 해소를 뜻하지 않는다. 게시 출력에서 `e_sqlite3.dll` 포함 및 로컬 JSON 제외를 확인했다. 이 게시 검증은 XML 인증키 전환 이전 결과다. 전환 후 Release 빌드와 88개 검증을 다시 통과했다.

실제 API 조회는 정상 응답·이력 2건·변경 문구 생성 여부를 확인했다. 실제 앱에서도 로그인 코드 일치, 응찰 서버 연결, 단일 테이블에 경매·이력·호출 제어의 당일 저장을 확인했다. 개인정보 및 원본 응답은 검증 기록에 남기지 않았다.

모든 사업장 계정·전광판 장비·글꼴·사용자 지정 화면 조합을 실제 운영 환경에서 검증한 것은 아니다. 공식 계정 한도와 여러 PC의 합산 사용량도 이번 로컬 검증 결과와 구분한다.
