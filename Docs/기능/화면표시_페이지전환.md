# 화면 표시와 페이지 전환

[기능 목차](README.md) · 확인 기준: 2026-10-01

## 표시 구조

- 대기·진행·낙찰·유찰에서 `AuctionItemDisplayViewModel`의 표시 값을 사용한다. 진행 화면의 소유 ViewModel 내부 `CowInfo`와 공통 표시 객체의 `Snapshot`은 역할에 따라 유지한다.
- 가격·중량 서식과 임신 표시 조건, 성별 표시가 이관됐다. Converter 전체 이관이 완료된 것은 아니다.
- 개체번호는 `EntityNumberText`가 하나의 TextBlock 안에서 Run으로 나누어 표시한다. 가운데 색상·굵기를 화면별로 정하며 `HighlightBackground`는 제거됐다. [사용법](../개체번호_공통표시_사용법.md)을 참고한다.
- 성별의 `비거세`·`미경산`은 원문을 유지하고 가로로 압축한다. `프리마틴`은 `프리`로 표시하며 화면별 색상·스타일은 XAML이 담당한다.
- 128×128 공통 비고는 `RunningNoteHost128` 하나를 사용한다. 원본 Note와 추가 이력은 출처별 색상을 유지하며, 원본 내용이 이력과 비슷하다는 이유로 자동 삭제하지 않는다.
- 해남진도(`8808990656106`)의 128×128 진행 화면은 송아지(`CowDistinction=1`)만 어미번호 행을 숨기고 브루셀라·구제역·최저가를 각각 세로 59·74·89픽셀에 배치해 15픽셀 간격으로 표시한다. 산차는 세로 91픽셀로 최저가 행에 맞춘다. 하단 비고와 친자 배지의 위치는 유지한다. 친자 배지는 기존 판정·표시 설정에 따라 하단 비고 앞에 노란 글자와 테두리로 표시한다. 비육우·번식우는 기존 양식을 유지하고 진행 화면의 친자 배지만 숨기며, 배지가 없으면 비고를 왼쪽부터 표시한다. 공통 호스트의 `UseCalfPaternityBadge`는 해남진도 진행 화면에서만 활성화되며 다른 사업장·낙찰·유찰의 배지 조건과 색상은 유지한다.

## 페이지와 화면 선택

- `DisplaySelect`와 `SetCustomDisplay`가 해상도·사업장·사용자 설정·품목에 맞는 진행·낙찰·유찰 화면을 고른다. 모든 사업장이 같은 전용 화면을 사용하는 것은 아니다.
- 2026-10-12 128×128 낙찰 기본 분기를 복원했다. 횡성(`8808990656885`)은 일반 경매 `HoengseongSold`, 가격 제목이 `행사용`이면 `HoengseongBunyangSold`를 사용한다. 다른 사업장의 기본 분기는 뿌리농가 표시 `X`일 때 `Standard_non_X_Sold`, 그 외 비육우·번식우는 `QQuriSold_Weight`, 나머지는 `QQuriSold`다. 장성·양평·예천·해남진도·화순의 기존 전용 분기와 염소·말 우선 처리를 유지한다. 과거 제거된 다른 사업장 전용 분기 전체를 복원한 것은 아니다. 제품과 GAMSTest는 같은 `AuctionViewFactory`를 사용한다.
- 요청 페이지 수와 실제 생성된 페이지 수를 구분한다. 3페이지 이력 화면도 해당 선택 분기로 생성돼야 표시된다.
- 진행 페이지를 미리 생성해 재사용한다. 이는 많은 전광판의 전환 지연을 줄이려는 기존 설계이며, 이번 문서 정리에서 생성·전환 방식을 바꾸지 않았다.
- MASTER는 로컬 회전을 구동하고 SUB는 동기 신호를 따른다. 설정된 시간 동안 신호가 없으면 SUB fallback이 로컬 회전을 수행할 수 있다.
- 단일 경매 진행과 첫 페이지 잠금은 순환을 제한한다. 일괄 경매 시작 신호 자체는 회전 정지 명령이 아니지만, 이미 정지한 타이머를 자동 재시작하는 것도 아니다.
- 하단 모드 상태줄은 페이지 수와 관계없이 표시한다. 1페이지일 때 숨기던 초기 설계는 변경됐다.

## 속초 128×64 전용 화면

2026-10-12 사용자 승인으로 통합 전 전용 화면 6종을 복원했다. 사업장 코드 8808990806426·Size128x64에서 가격 제목을 Trim한 값이 `행사용`이면 SokchoEventRun_64 한 페이지, 낙찰·유찰은 SokchoEventResult_64를 사용한다. 일반 경매는 SokchoRunning1_64·SokchoRunning2_64 최대 두 페이지, 결과는 SokchoSold_64·SokchoUnSold_64다. 속초 128×128도 이전처럼 요청 페이지 수 최대 2를 유지하며, 다른 사업장·해상도 분기는 유지한다.

제품과 GAMSTest는 공통 AuctionViewFactory의 전용 선택과 페이지 목록을 사용한다. 로그인 후 사업장 갱신 시 페이지 제한을 적용하고 일반 화면·속초 일반·행사의 캐시 이름을 구분한다. 원본 좌표·색상·글꼴·고정 문구를 보존했고 가격 바인딩과 진행 비고 애니메이션 수명만 현재 구조에 연결했다. 2026-10-12 후속 적용으로 진행 1·2페이지의 개체번호는 하나의 `EntityNumberText`에 표시하며 가운데 네 자리 글자색을 강조한다. 번호 위치·11pt와 노란색 본문·흰색 강조색을 사용한다. 현장 화면·실제 수신·배포 확인은 별도다.

## 운영 해상도·배치 기준

2026-10-12 사용자 제공 기준이며 아래 계산은 슬롯 128×128, Windows 배율 100% 기준이다. 9행×25열은 현재 샘플 XML 배치이며 제품의 고정 최대 배치가 아니다.

| 화면 구성 | 해상도 | 사용자 최대 배치 | 슬롯 수 | 슬롯 영역 |
| --- | --- | --- | --- | --- |
| 단일 | 2560×1600 | 11행×20열 | 220 | 2560×1408 |
| 단일 | 3840×1080 | 7행×30열 | 210 | 3840×896 |
| 듀얼 | 5120×1600 | 11행×40열 | 440 | 5120×1408 |
| 듀얼 | 7680×1080 | 7행×60열 | 420 | 7680×896 |

사용자 최적 배치는 8행×40열(320슬롯, 5120×1024)과 6행×60열(360슬롯, 7680×768)이다. 남는 세로 공간과 배율·창 시작 위치·하단 상태 영역을 고려해야 한다. 원본 Board.XML·users.XML은 이번 기준 확인으로 변경하지 않았다. GAMSTest에는 현재 최대 400슬롯 제한이 있어 최적 배치는 지원하지만 최대 듀얼 440/420슬롯은 거부한다. 이 제한 변경과 실제 장비·DPI 검증은 별도 작업이다.

## 메인뷰 하단 상태 영역

- 로그 위에 응찰서버 연결, 마스터·서브 역할, 경매 방식·진행, 뿌리농가 설정, 현재/전체 페이지, 회전 상태와 버전을 구획별로 표시한다. 구간 정보는 페이지 상태와 버전 사이에 표시하고, 최근 신호와 이력 처리 안내는 그 아래 흰색 두 줄로 유지한다. 범위는 `구분 1(송아지) · 1구간 · 경매프로그램 선택 구간 1~999번` 형식으로 표시해 구간 번호를 보존한다.
- 표시 순서는 페이지 상태 → 구간 정보 → 버전이며 좁은 창에서는 항목을 줄바꿈한다. 항목 안쪽 여백은 좌우 12·상하 5, 최소 높이는 28이다. 구간 정보가 비어 있으면 해당 셀을 숨긴다. 실제 상태 영역 높이를 창 높이에 반영하며 초록색 로그 행 높이 70과 이력 새로고침 메뉴를 보존한다.
- 페이지 상태는 실제 로컬 타이머 실행 여부를 사용한다. MASTER의 `전환 중`/`정지`, 정상 SUB의 `동기화 수신 모드`, SUB fallback의 `로컬 복구`를 구분한다. 원격 타이머 실행을 추측하지 않는다. 고정 사유는 툴팁에 표시한다.
- 경매 상태는 구조화된 수신 값으로 표시한다. 초기·방식 전환·새로고침의 미확인을 종료로 오인하지 않고, 예정가 변경 8003을 경매 시작으로 표시하지 않는다. 연결 실패·종료 시 이전 경매 표시를 초기화하고 실패 중 늦은 갱신을 무시한다.
- 담당: [MainWindow](../../Views/MainWindow.xaml), [MainWindowViewModel](../../ViewModels/MainWindowViewModel.cs), [MainStatusViewModel](../../ViewModels/MainStatusViewModel.cs), [AuctionDisplayState](../../Domain/Auction/AuctionDisplayState.cs).
- 2026-10-01 최종 배치 빌드 경고 0·오류 0, `footer` 119개 통과. 구간 명칭 변경 시 `stage3` 594개, 통합 구현 시 `stage4` 837개 통과 기록이 있다. 후속 배치 변경에서 관련 없는 검사를 반복하지 않았다. 실제 운영 수신·전광판·다중 PC와 여러 시스템 DPI는 미검증이다. [완료 계획](../계획/완료/메인뷰_하단상태바_통합계획_2026-10-01.md) 참조.

## 애니메이션과 이력 갱신

`FlowTextAnimation`은 보이지 않는 텍스트의 애니메이션을 멈추고, Unloaded 및 종료 시 관련 이벤트·예약 작업을 정리한다. 공통 비고는 같은 개체·같은 문구의 스크롤 위치를 이어간다. 이력만 바뀌는 경우 `UpdateHistoryDisplay`가 기존 페이지와 스크롤을 유지하며 해당 표시 값을 갱신한다.

이 동작을 모든 XAML Storyboard가 숨김 상태에서 멈춘다는 의미로 확대하지 않는다.
