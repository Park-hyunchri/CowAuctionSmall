# 설정과 로그

[기능 목차](README.md) · 확인 기준: 2026-10-01

XML 설정 파서는 `Infra/XmlSettings`에 있다. 기존 `Infrastructure/Configuration`의 폴더·네임스페이스 명칭만 변경했으며 XML 파일 경로와 설정 형식은 유지한다.

## 설정의 책임

| 위치 | 책임 |
| --- | --- |
| `Config/users.XML` | 로그인·통신·화면·이력 등 사용자 설정. 실제 실행본이 읽는 복사본과 구분 |
| `Config/Board.XML` | 전광판 배치·계류대 등 보드 구성 |
| `Infra/XmlSettings/UserXmlParser.cs` | 사용자 XML을 모델로 변환하고 기본값 적용 |
| `Infra/XmlSettings/BoardXmlParser.cs` | 보드 XML 해석 |
| `NLog.config` | 파일 로그 출력 정책 |

로그인 이후 실제 통신과 화면의 사업장 기준은 인증 응답의 사업장 코드다. XML 사업장 코드는 비교용 예상값이며, URL 자리 표시자는 인증된 코드로 해석한다. 설정값과 로그인 사업장이 다르면 XML만 보고 화면 분기를 판단하면 안 된다.

이력 조회·비고 숨김·요청 간격은 [이력 기능 문서](이력조회_캐시.md), 페이지와 MASTER/SUB 설정은 [화면 기능 문서](화면표시_페이지전환.md)를 참고한다. 실제 운영 인증값이나 서버 주소를 사용 예시에 복사하지 않는다.

## 빌드·게시 자동 버전

2026-10-12 사용자 요청으로 출하 AMS와 출하 AMS 테스트의 날짜·시간 자동 버전을 복원했다. 두 프로젝트는 `1.1.<2000-01-01 이후 일수>.<빌드 PC의 당일 경과 초 ÷ 2를 정수 변환한 값>`을 Version·AssemblyVersion·FileVersion·InformationalVersion에 동일하게 적용한다. 제품 버전에 Git 해시를 붙이지 않는다.

유지 이유: 서로 다른 수정본이 같은 고정 버전으로 표시되면 현장 EXE 식별, 장애 당시 사용 버전 추적, 배포 교체 확인이 어려워진다. 고정 `1.0.1.30`과 테스트 앱의 버전 설정 누락을 반복하지 않도록, 사용자 명시적 요청 없이 자동 버전 속성을 제거하거나 고정 숫자로 대체하지 않는다. 소스 수령·통합 시 기능 변경과 별개로 두 프로젝트의 버전 설정을 보존한다.

- 담당: [출하 AMS](../../CowAuctionSmall.csproj), [출하 AMS 테스트](../../Tools/GAMSTest/GAMSTest.csproj). 두 앱은 같은 규칙을 쓰지만 프로젝트 평가 시각이 다르면 실제 버전값은 다를 수 있다.
- Debug·Release 및 실제 빌드를 포함하는 게시에 적용한다. 기존 바이너리를 쓰는 `--no-build` 게시나 IDE의 빌드 생략 시에는 기존 버전을 유지한다.
- 시간값은 약 2초 단위이며 같은 구간의 빌드는 같은 버전일 수 있다. PC 시계·날짜가 되돌아가면 버전도 되돌아갈 수 있으므로 전역 고유 번호나 Git commit 식별자를 대신하지 않는다.
- 소스 파일이나 별도 증가 카운터를 빌드할 때마다 수정하지 않는다. 패키지·런타임·게시 출력 위치는 버전 설정과 별개로 관리한다.
- 검증 시 두 앱의 파일·제품·어셈블리 버전이 숫자 `1.1.x.x`로 일치하는지 확인한다. 기준 변경은 사용자 승인과 변경 이유·검증 결과 기록이 필요하다.

## 로그와 상태줄

- Visual Studio Debug 출력은 `AsyncDebugOutput`의 별도 작업자에서 처리한다. 경매 처리 경로가 매번 디버거 출력 완료를 기다리지 않도록 한다.
- 파일 로그는 NLog 비동기 경로를 사용한다. Debug 출력과 파일 기록은 별개의 출력 경로다.
- 출력 큐에는 한계가 있다. 포화 시 누락 통계가 발생할 수 있으므로 로그가 없다는 이유만으로 패킷 미수신을 확정하지 않는다.
- 통합 상태바는 응찰서버·역할·경매·페이지·구간·버전 순서이며 최근 수신 신호와 이력 처리 진행률은 아래 두 줄에서 구분한다. `OnStringArrMsg` 같은 함수명만으로 업무 신호를 판단하지 않는다.
- 로그의 `timer=off`는 페이지 전환 타이머의 정지 상태다. MASTER 표시는 PC의 역할이며, 역할이 MASTER라는 것만으로 페이지가 순환 중이라고 판단하지 않는다.

## 오늘 이외 로그 자동 압축

`LogArchiveService`가 현재 NLog 저장 위치인 **실행 파일 폴더의 Logs/** 하위 `.log`를 압축한다. 앱 시작 직후와 이후 1시간마다 낮은 우선순위의 전용 백그라운드 스레드 하나가 순서대로 처리한다. 새 패키지나 사용자 설정 항목은 필요하지 않으며 기존 NLog 비동기 기록을 유지한다.

- 오늘은 PC의 로컬 날짜 기준이다. 로그 파일명 앞의 `yyyy-MM-dd` 또는 상위 날짜 폴더가 오늘이면 원본을 유지한다. 날짜 표기가 없는 로그는 마지막 수정일을 사용한다. 두 달 보관 기간 안의 오늘 이외 `.log`를 압축하며, 새 ZIP의 마지막 수정일도 원본과 같게 유지한다.
- 예: `Logs/2026-09-30/2026-09-30.log` → 같은 폴더의 `2026-09-30.log.zip`. 파일별 ZIP에 원래 이름의 로그 하나를 넣는다. 2026-10-12 사용자 요청으로 무기한 보관을 대체해 아래 두 달 자동 삭제 정책을 적용한다.
- 원본을 다른 쓰기와 겹치지 않게 독점해서 열고 임시 ZIP을 만든다. 완료 파일을 게시한 뒤 ZIP을 읽어 길이·파일명·SHA-256이 원본과 일치하는지 검증한다. 성공한 경우에만 잠긴 원본 핸들로 삭제를 예약해 닫을 때 정리한다. [Windows 파일 핸들 삭제 API](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)의 DELETE 접근 권한과 FileDispositionInfo를 사용한다.
- 같은 이름의 ZIP이 있으면 내용을 검증하고 재사용한다. 내용이 다르거나 손상되면 기존 ZIP을 덮어쓰지 않고 내용 해시를 붙인 별도 ZIP으로 보존한다. 대체 ZIP까지 손상되어 검증할 수 없으면 원본을 남긴다.
- 사용 중인 파일·권한 부족·압축/검증 실패는 원본을 유지하고 다음 주기에 재시도한다. 링크·정션을 따라 Logs 밖으로 나가지 않는다. 파일 경로·로그 본문을 추가 진단에 기록하지 않고 완료·유지·재시도 건수만 남긴다.
- 앱 종료 시 취소를 요청하고 최대 1초만 기다린 뒤 기존 로깅 종료 절차를 따른다. ZIP 게시 후 원본 정리 전에 중단되었으면 다음 실행에서 검증 후 이어서 정리한다. 정상 취소·실패는 해당 작업의 임시 파일을 정리한다. 프로세스 강제 종료로 임시 `.tmp`가 남더라도 검증되지 않은 ZIP을 근거로 원본을 삭제하지 않는다.

이 기능은 현재 프로젝트의 Logs 경로를 대상으로 한다. 다른 프로그램의 로그나 디스크 전체 `.log`를 검색하지 않는다. 검증은 별도 임시 폴더의 가상 로그로 수행했으며 기존 운영 로그의 일괄 압축이나 운영 앱 실행은 수행하지 않았다. 새 빌드로 앱을 실행하면 자동 처리가 시작된다.

### 두 달 이상 로그 자동 삭제

- 사용자 요청 이유: 무기한 ZIP 보관으로 디스크 관리 인력과 시간이 계속 소모되는 것을 방지한다. 앱 시작과 이후 1시간마다 기존 압축 작업자에서 만료 파일을 먼저 정리한다. 별도 설정은 필요하지 않는다.
- 기준은 PC 로컬 날짜의 `오늘.AddMonths(-2)`까지(경계일 포함)다. 60일 고정이 아니며 윤년·월말은 달력 계산을 따른다. 예: 2026-10-12 실행 시 2026-08-12와 이전 로그가 대상이다.
- 실행 폴더의 Logs 하위 `.log`, `.log.zip`, 이 서비스의 SHA-256 충돌 처리 형식 `.log.<64자리 해시>.zip`만 삭제한다. 만료 원본은 압축하지 않고 삭제한다. 일반 ZIP·다른 확장자·임시 `.tmp`·폴더는 삭제하지 않는다.
- 파일명 날짜와 상위 날짜 폴더가 다르면 더 최신 날짜를 사용해 최근 로그를 보호한다. 날짜가 없으면 파일의 마지막 수정일을 사용한다. 기존 날짜 없는 ZIP은 당시 수정일을 기준으로 한다.
- 경로를 확인하고 독점 핸들을 얻은 뒤 날짜·경로·취소 여부를 재확인해 같은 핸들로 삭제한다. 사용 중·읽기 전용·권한 부족은 보존하고 다음 주기에 재시도한다. 링크·정션은 따라가지 않는다. 처리 결과의 `만료삭제` 건수를 로그에 표시한다.
- 새 제품 EXE로 실행할 때 적용된다. 기존 운영 로그의 수동 일괄 삭제와 현장 배포는 수행하지 않았다. GAMSTest는 제품 App을 실행하지 않으므로 운영 로그 정리를 시작하지 않는다.

## 뿌리농가 표시 설정 Y·N·X

`IsShowQQuri`의 N은 제거되지 않았다. Y는 서버 뿌리농가·농협 우량 정보를 반영하고, N은 해당 정보 활성화 경로를 사용하지 않으며, X는 별도의 미적용 화면 선택을 위한 값이다. 진행 화면에서 일반 비참여 경로와 X 전용 경로는 서로 다르므로 기존 N을 일괄 X로 변경하지 않는다. 사업장 전용 화면은 별도 분기가 우선한다. 일반 낙찰 화면은 Y/N에 대해 공통·중량 화면을 사용하고 X에서는 Standard_non_X_Sold를 사용한다.
