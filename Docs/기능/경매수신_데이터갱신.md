# 경매 수신과 데이터 갱신

[기능 목차](README.md) · 확인 기준: 2026-10-06

## 현재 동작

1. Netty 수신을 해석하고 `AuctionIngress`를 통해 경매 상태 변경을 순서대로 처리한다. 외부 조회 응답은 요청 세대·날짜 등 현재 상태와 맞는지 확인한다.
2. `SV`는 한 경매품의 제공된 필드를 갱신한다. 목록 API의 전체 스냅샷과 같은 필드 순서라고 가정하지 않으며, SV에 없는 필드를 임의로 비우지 않는다.
3. `AuctionItemStore`가 기존 값과 비교해 변경된 개체를 반영한다. 중복 수신과 실제 변경을 구분하고, 오래된 조회 응답이 더 최근 정보를 덮어쓰지 않도록 처리한다.
4. `DataChangedMessage`를 통해 전체 목록과 부분 갱신을 구분해 화면에 전달한다. 보드의 전체 행 수와 실제 표시 수는 계류대·배치 조건 때문에 다를 수 있다.
5. `AnimalParseData`는 공통 필드를 먼저 파싱한 뒤 반환 직전에 축협별 표시 규칙을 적용한다. 현재 별도 규칙은 횡성 성별, 익산·군산 지역 및 비고 친자 문구, 상주 지역, 영천·보령 임신 개월, 장성 비고 앞글자다. `ChangeSexName`의 일반 성별 변환과 `IsPaternityMatch`의 최종 표시 여부는 공통 규칙으로 유지한다.

익산·군산(`8808990227283`)은 공통 `data[23]` 친자 판정에 더해 비고에서 `친자일치`, `친자 일치`, `친자확인`, `친자 확인`을 찾는다. 여러 문구가 있으면 비고에서 가장 먼저 나오는 문구 하나를 친자일치로 반영하고 그 문구만 비고에서 제거한다. 나머지 비고 내용은 유지한다. `IsPaternityMatch=N`이면 문구 보완과 제거를 하지 않으며 최종 공통 숨김 규칙도 유지한다. 이 예외는 익산·군산에만 적용한다.

이 경매 데이터 갱신과 [이력 결과의 개체별 반영](이력조회_캐시.md)은 서로 다른 처리 경로다.

## 주요 신호

| 신호 | 현재 책임과 주의점 |
| --- | --- |
| `AT` | 경매 방식 전환. `10`은 일괄, `20`은 단일 경매 |
| `AS` | 경매 상태 전달. 단일·일괄 방식별 처리와 목록 재조회 분기가 있음 |
| `SV` | 개체 정보·예정가 등 제공된 데이터의 변경 반영 |
| `AF` | 낙찰·유찰 등 결과 처리 |
| `SZ` | 표시 명령·날짜·축종·구간 수신. `P/Y/N`은 날짜 기준 재조회 경로, `A/H`는 수신 안내와 메타데이터 처리 |
| `SD` | 카운트다운·정지 관련 수신 안내 및 기존 상태 처리 |

버튼 조작과 실제 수신의 과거 관찰은 [경매 프로그램 검증 자료](../경매프로그램/README.md)를 참고한다. 해당 자료에는 별도 MAUI 프로그램의 결과도 포함된다.

## 축종·구간 안내

- 축종은 `0 전체`, `1 송아지`, `2 비육우`, `3 번식우`로 표시한다. 경매 방식 AT10/20과 다른 값이다.
- 유효한 SZ에는 날짜·구간 시작/끝 번호가 포함된다. AS의 구간 번호만으로 범위를 확정할 수 없으면 별도 API 조회로 보완한다.
- `AuctionSectionLookup`은 중복 조회를 합치고 성공·실패 결과를 일정 시간 재사용한다. 날짜·사업장·축종·구간이 바뀐 뒤 도착한 이전 결과는 표시하지 않는다.
- 현재는 상태줄의 구간 안내 기능이다. 수신 구간과 미응찰 조건을 적용하는 전용 목록 필터까지 구현한 것으로 해석하지 않는다.
