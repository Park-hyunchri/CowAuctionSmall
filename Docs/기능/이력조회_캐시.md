# 이력 조회와 캐시

[기능 목차](README.md) · 확인 기준: 2026-10-01

## 현재 동작

현재 표시 대상의 원본 이력번호로 캐시를 먼저 확인하고 필요한 개체를 백그라운드에서 조회한다. 캐시·API·초기 조회·당일 추가 등록 모두 **결과가 준비된 개체부터 반영**한다. 전체 완료나 500ms 묶음 타이머를 기다리는 이전 방식은 대체됐다.

동일 개체의 요청을 공유하고 화면 대상이 바뀌면 더 이상 필요 없는 작업을 취소한다. 결과는 대상 개체·조회 요청·캐시 날짜가 여전히 맞는 경우에만 해당 슬롯에 적용한다. UI 적용을 기다리는 작업 수도 제한하며, 경매 가격·상태·원본 비고를 이력 응답으로 덮어쓰지 않는다.

## 사용자 설정

아래는 동작 설명용 예시이며 운영 파일을 변경한 내용이 아니다.

```xml
<AnimalTrace>
  <IsAnimalProductsTraceability>Y</IsAnimalProductsTraceability>
  <ShowOwnerChangeNote>N</ShowOwnerChangeNote>
  <RequestIntervalMs>1000</RequestIntervalMs>
  <ServiceKey>발급받은 인증키</ServiceKey>
</AnimalTrace>
```

| 항목 | 현재 의미 |
| --- | --- |
| `IsAnimalProductsTraceability` | Y이고 인증키가 있어야 이력 조회 사용. N이면 이력 조회 미사용 |
| `ShowOwnerChangeNote` | N이면 추가 소유주 변경 비고를 숨김. 조회·캐시·이력 화면의 소유주와 사육지 제공은 유지. 누락 시 기본값은 표시 |
| `RequestIntervalMs` | 새 API 요청 시작 간격. 기본 1000ms, 양수 250ms 미만은 250ms로 보정, 0 이하·해석 불가는 기본값 |
| `ServiceKey` | 이력 API 인증키. 문서·로그에 실제 값을 기록하지 않음 |

설정 반영에는 앱 재시작이 필요하다. 동시 요청 수 기본값은 1이며 소스 설정은 1~4 범위를 지원한다. 요청 간격이 개별 HTTP 응답 시간을 보장하지는 않는다.

## 비고와 최신 소유주·사육지

- 소유주 변경 비고는 양수 이력 등 문구 생성 조건에 맞는 경우에만 추가한다. 조회 성공 건수와 비고가 생긴 건수는 다르다.
- 최신 소유주와 `farmAddr`는 같은 신고 이력에서 이름·주소 쌍으로 가져온다. 최신 날짜의 기록이 모호하면 임의로 하나를 고르지 않는다.
- 이력 조회 화면은 이 이름·사육지를 사용한다. 주소 표시에서는 선행 도·특별시·광역시 등 광역 행정구역명을 생략하는 서식을 사용한다. 원본 데이터와 화면 서식은 구분한다.
- 원래 서버 Note는 보존한다. 원본은 빨간색, 추가 이력은 흰색으로 표시하며, `ShowOwnerChangeNote=N`은 추가 이력 부분만 숨긴다.

## SQLite 보관

`daily_cache` 단일 테이블에 경매·개체 이력·호출 제어 데이터를 구분해 저장한다. 위치는 `%LOCALAPPDATA%\CowAuctionSmall\Cache\<설치 경로 해시>\auction-cache.db`이다.

테이블 스키마 `user_version=1`과 이력 JSON 내용 버전 2는 다른 값이다. 현재 이력에는 필요한 날짜·신고 유형·소유주·사육지를 저장한다. 원본 API XML 전체나 인증키를 캐시에 저장하지 않는다. 주소가 없는 구버전 이력 캐시는 재조회 대상이다.

화면에서 빠진 개체의 정상 캐시도 당일까지 재사용한다. 시작·DB 접근·실행 중 날짜 점검에서 만료 데이터를 정리하고, 이전 날짜 요청이 늦게 끝나도 현재 화면에 반영하지 않는다. 정상 빈 결과도 캐시되므로 반복 수신마다 같은 이력을 다시 요청하지 않는다.

## 남은 확인

- 여러 PC의 합산 API 사용량과 제공기관 허용 조건, 많은 전광판에서의 실제 표시 지연은 별도 확인 대상이다.
- 개체별 반영은 준비된 순서이며 출품 번호순 완료를 보장하지 않는다.
- 같은 날 정상 빈 결과를 캐시한 뒤 외부 이력이 새로 등록되는 경우의 갱신은 수동 새로고침·기존 재조회 정책과 함께 확인해야 한다.
