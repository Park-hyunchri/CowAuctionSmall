# GAMSTest 전광판 점검 도구

기준일: **2026-10-01**. 참고 GAMSTest의 제어창 UI를 유지하고 Board.XML 선택을 추가한 별도 WPF 프로그램이다. 가상 자료와 현재 제품의 실제 경매 화면을 사용한다. 도구 자체는 로그인·Netty·HTTP·UDP 동기화·운영 SQLite 조회를 시작하지 않는다.

## 실행과 사용

Visual Studio에서 GAMSTest를 시작 프로젝트로 지정하거나 저장소 루트에서 실행한다.

```powershell
dotnet run --project Tools/GAMSTest/GAMSTest.csproj
```

제어창은 참고 실행 파일과 같은 460×210 크기로 화면 왼쪽 아래에 열린다. 기존 버튼 배치·색상·밝기 슬라이더·아이콘을 유지하고 `출하 AMS` 아래에 `Board.XML 열기` 버튼을 추가했다. `출하 AMS` 위의 선택 상자는 현재 보드 크기를 표시하며 128×64·128×128·160×64·320×64를 직접 선택할 수 있다. XML을 열면 파일의 Size가 선택되며 이후 수동 변경은 점검 중 메모리에만 적용한다. XML을 다시 열면 파일의 크기로 돌아온다.

1. 시작할 때 XML 표시 설정을 자동으로 읽고 계류대 번호를 표시한다.
2. `번호`, `진행`, `유전`, `유찰`, `낙찰`로 화면을 바꾼다. 개별 `진행`·`유전` 선택은 테두리가 깜박이지 않는다. 같은 경매 화면을 다시 누르면 화면과 비고 애니메이션을 재시작하지 않는다. 자동 순환 중 수동 선택은 같은 화면이어도 순환과 테두리 깜박임을 멈춘다.
3. `레드`, `그린`, `블루`, `화이트`, `블랙`으로 단색을 확인한다. 밝기는 0~255이며 기본값은 기존과 같은 170이다. 밝기를 조절하면 마지막으로 선택한 단색으로 전환된다.
4. `뷰 페이지`는 진행 페이지 → 유찰 → 낙찰 순서로 5초마다 순환하며 진행 화면의 테두리는 기존처럼 깜박인다. 수동 화면·번호·단색 선택은 순환을 멈춘다.
5. `Board.XML 열기`에서 원하는 경로의 XML을 선택하면 크기·첫 MultiBoard 배치·번호를 즉시 적용하고 번호 화면으로 전환한다. 취소·파일 읽기 실패·잘못된 배치는 기존 화면과 순환 상태를 유지한다. 버튼에 마우스를 올리면 현재 읽은 파일 경로가 표시된다.
6. 제어창 또는 표시창을 닫으면 타이머·화면·창을 정리하고 종료한다.

`출하 AMS`는 이미 실행 중인 CowAuctionSmall을 앞으로 가져오거나 실행 파일을 찾아 실행한다. 찾지 못하면 파일 선택창을 연다. 이 버튼으로 실행하는 경매 프로그램은 자체 운영 통신을 수행할 수 있다. 점검 도구 시작만으로 경매 프로그램을 실행하지 않는다.

## 외부 전광판 제어 프로그램 연동

2026-10-12 이전본의 Named Pipe 규약을 복원했다. Pipe 이름은 `GAMSTest.DisplayCommand`이며 로컬 Windows 경로는 `\\.\pipe\GAMSTest.DisplayCommand`다. 기존처럼 한 연결에서 텍스트 명령 한 줄을 받고 다음 연결을 기다린다. 대소문자는 구분하지 않고 앞뒤 공백은 제거한다.

| 명령 | 동작 |
| --- | --- |
| `NUMBER` | 현재 Board.XML 배치의 계류대 번호 표시, 자동 순환 중지 |
| `RED`·`GREEN`·`BLUE` | 선택한 단색 표시, 자동 순환 중지, 현재 밝기 적용 |
| `STOP` | 제어창·표출창 종료, 타이머·화면 캐시·Pipe 수신 정리 |

STOP은 출하 AMS 실행 버튼을 호출하지 않는다. 단독 실행 시 기존 번호 자동 표시를 유지하며, 빈 명령·알 수 없는 명령은 화면을 바꾸지 않는다. 연결이 끊겨도 다음 연결을 받을 수 있다. 수신 작업은 UI Dispatcher로 전달하고 종료 후 예약된 명령은 무시한다.

외부 제어 프로그램에서 사용하려면 수정된 GAMSTest.exe로 테스트 도구를 실행해야 한다. 실행 경로가 이전 EXE를 가리키면 새 소스의 수정은 반영되지 않는다. 이 규약은 Named Pipe이며 별도 TCP/UDP 수신 포트를 추가한 기능은 아니다. 실제 외부 프로그램·원격 PC·전광판 연동은 현장 확인 대상이다.

## 단일 EXE 배포

출하 AMS 테스트의 파일·제품·어셈블리 버전은 출하 AMS와 같은 날짜·시간 자동 생성 규칙 `1.1.<일수>.<시간값>`을 유지한다. 현장 수정본 식별과 배포 확인을 위해 고정 버전으로 되돌리지 않는다. [자동 버전 기준과 유지 이유](설정_로그.md#빌드게시-자동-버전)를 참고한다.

현장 배포는 Windows x64용 **GAMSTest.exe 한 개**를 사용한다. .NET과 Windows Desktop 런타임, 필요한 DLL, 기본 가상 XML을 포함하므로 별도 .NET 설치나 Examples 폴더 없이 실행할 수 있다. 외부 Board.XML은 기존 열기 버튼으로 선택하며 운영 users.XML은 필요한 경우 별도 Config에 둔다. 출하 AMS 실행 파일은 별도 프로그램으로 유지한다.

Visual Studio에서는 GAMSTest의 게시 메뉴에서 [SingleFile-win-x64 프로필](../../Tools/GAMSTest/Properties/PublishProfiles/SingleFile-win-x64.pubxml)을 선택한다. 명령줄은 다음과 같다.

```powershell
dotnet publish Tools/GAMSTest/GAMSTest.csproj -c Release -p:PublishProfile=SingleFile-win-x64
```

기본 게시 위치는 `Tools/GAMSTest/bin/Release/net10.0-windows/win-x64/publish-single/`이다. 일반 빌드의 bin 폴더와 구분한다. 검증이나 배포 후보를 만들 때는 `--artifacts-path <임시 빌드 경로> -o <별도 게시 경로>`로 기존 배포본과 분리할 수 있다.

- SelfContained·PublishSingleFile·IncludeNativeLibrariesForSelfExtract를 사용한다. WPF 화면과 바인딩을 유지하기 위해 트리밍은 사용하지 않는다.
- 제품 프로젝트는 실행 파일이지만 GAMSTest에서는 화면 DLL로 참조한다. 이 프로필에만 ValidateExecutableReferencesMatchSelfContained=false를 설정하며 제품의 배포 설정은 변경하지 않는다.
- 기본 예제 XML은 어셈블리 리소스로 포함한다. 별도 PDB·운영 Config·NLog.config는 배포하지 않는다.
- 단일 파일은 배포 형태를 뜻한다. 실행 시 네이티브 구성 요소는 `%TEMP%/.net` 등에 풀릴 수 있다. [Microsoft 단일 파일 배포 문서](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)
- 2026-10-01 확인본은 147,565,391바이트(약 140.7MiB)다. 내장 런타임은 .NET/Windows Desktop 10.0.12이며 SDK·의존성에 따라 크기와 버전은 달라질 수 있다.

## 설정 읽기

다음 순서로 Board.XML 또는 users.XML이 있는 첫 디렉터리를 선택하고 그 디렉터리의 파일만 읽는다.

1. 실행 파일 폴더의 `Config/`
2. 현재 작업 디렉터리의 `Config/`
3. 실행 파일의 상위 경로에서 찾은 현재 소스 저장소의 `Config/`
4. 실행 파일 폴더의 `Examples/`가 있을 경우 이전 방식의 외부 예제 설정
5. 위 경로에 설정이 없으면 EXE 내부의 가상 Board/users XML

- Board.XML: 해상도와 첫 번째 MultiBoard의 RowIdx 배치를 사용한다.
- users.XML: StartPosition, 사업장 코드, 페이지 수, 뿌리농가, 이름·성별·생일·친자·중량/EPD·가격 제목·색상 등 표시 설정을 읽는다. 인증정보·서버 주소·API 키는 설정 객체에 보관하지 않는다.
- 파일 열기는 Board 설정만 교체한다. 기존 users.XML의 사업장·색상·표시 옵션·표시창 위치는 유지한다. 선택 경로는 실행 중에만 보관하며 재시작하면 기본 탐색 순서를 사용한다.
- 원본 XML은 변경하지 않는다. 설정이 없으면 기본 가상 배치를 사용한다. 기본 예제는 EXE 내부에 포함된 2행×4열의 가상 설정이며 파일로 풀어 쓰지 않는다.
- 운영 Config와 NLog.config는 빌드·게시 결과에 자동 복사하지 않는다. 현장 배치는 `Board.XML 열기`로 선택할 수 있다. 시작부터 자동 적용하려면 도구 옆 Config에 표시 설정을 준비한다.
- 별도 설정 편집창·배치 선택창은 없다. 첫 MultiBoard를 쓰는 동작은 참고 도구와 동일하다.

## 지원 화면

| 해상도 | 번호·단색 | 경매 화면 |
| --- | --- | --- |
| 128×64 | 지원 | 일반 진행 최대 4페이지. 속초는 일반 2페이지·행사 1페이지와 전용 낙찰·유찰 화면. 사업장별 순서 반영 |
| 128×128 | 지원 | 진행 1·2페이지, 지원 사업장 3페이지, 낙찰·유찰 |
| 160×64 | 지원 | 진행 1·2페이지, 낙찰·유찰 |
| 320×64 | 지원 | 진행 1페이지. 현재 제품에서 미구현인 유전·낙찰·유찰 버튼은 비활성화 |

자동 순환의 진행 페이지 수는 BoardPage와 실제 지원 범위를 따른다. 수동 `유전` 버튼은 지원되는 진행 2페이지를 직접 표시하므로 BoardPage가 1이어도 사용할 수 있다. 페이지 구성과 순서는 제품의 선택 규칙을 따른다.

표시창은 테두리·스크롤바 없이 전체 배치 크기를 사용한다. 번호 화면은 기존 파란 테두리·흰색 번호·‘경매번호’ 문구를 유지하고 64 높이에 맞춰 글자 크기와 여백을 조절한다. 실제 픽셀 대응은 Windows DPI와 장비 출력 배율을 확인해야 한다.

## 구현과 검증

제품의 실제 View·표시 ViewModel·공통 비고 호스트·색상 리소스를 재사용한다. 동일 설정에서는 슬롯별 화면을 캐시하고 하나의 타이머로 전환한다. 128×128 공통 비고를 쓰는 진행 페이지는 슬롯마다 비고 호스트 하나를 유지하고 본문만 교체하므로 진행·유전 전환 중 비고 애니메이션이 계속 이어진다. 자체 비고가 있는 예외 화면이나 다른 해상도는 기존 화면 구성을 사용한다. 비활성 화면은 DataContext를 해제하고 화면에서 분리하며 설정 변경과 종료 시 캐시·이벤트·ViewModel을 정리한다.

표시 값은 가상 자료이며 서버 패킷이나 API 성공 여부를 검사하지 않는다. RGB 밝기는 색 강도로, 전광판 제어기의 하드웨어 밝기 설정과는 별개다. 긴 이름·빈 값·100/200슬롯 검사는 검증 프로젝트에 남아 있으며 제어창에는 별도 버튼을 추가하지 않았다.
